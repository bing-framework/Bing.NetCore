# 全量测试失败修复与真实数据库验收计划

## 1. 目标与已确认范围

新任务标识：`20261022-full-suite-recovery`。

修复迁移验收发现的 **181 项失败**，分别验证默认本地测试和显式启用的数据库集成测试：

| 失败类别 | 数量 | 当前诊断 |
|---|---:|---|
| MySQL / SQL Server | 154 | 项目自动加载本地 runsettings，覆盖外部门控；其中 2 项涉及三 Provider 混用 |
| Logging | 24 | 注册阶段读取配置失败，测试还依赖固定磁盘路径和 Seq |
| AOP 取消传播 | 2 | 代理快速完成路径可能遗漏取消状态，需要确定性回归验证 |
| EventBus 退避 | 1 | 用固定等待时间后的次数判断退避，受线程调度影响 |

按已确认选择，启动独立 MySQL、SQL Server 和 PostgreSQL 测试环境；PostgreSQL 仅用于原混合 Provider 用例。

保持 SDK 10.0.400、SLNX、包版本、公共 API、既有功能代码及性能预算。

## 2. 修复方案

### T01：固定失败清单与测试配置来源

- 保存本任务涉及文件的工作区起点，引用原始 TRX，不改写迁移报告。
- 按“测试项目＋完整方法名＋TFM”建立 181 项失败清单，记录修复和复验结果。
- 区分本地 runsettings、命令参数及进程环境变量，诊断日志不记录连接密码。

### T02：修复本地配置隐式启用外库的问题

现有 Fact/Theory 和 fixture 门控已经存在，不重新实现。

- 移除四个 SQL 集成项目自动加载 `integration.local.runsettings` 的行为；配置必须通过 `dotnet test --settings` 或现有 Provider runner 显式传入。
- 保留用户本地配置文件，不删除、不改写凭据。文档明确普通 VSTest 与 Provider runner 各自支持的配置入口。
- 保持默认外库关闭、SQLite 本地测试运行；启用后缺配置、连接失败或 SQL 错误必须失败，不能转为跳过。
- 将 MySQL 中无需数据库的注册测试移出数据库 collection，避免被 fixture 的连接初始化牵连。
- 增加配置选择回归：默认不加载本地文件、显式设置生效、关闭时不初始化外库、启用后错误不被隐藏。用独立测试进程验证环境变量，避免污染其他测试。

### T03：使 Logging 测试自包含

- 通过宿主提供的 `HostBuilderContext.Configuration` 配置 Serilog，不在服务注册期调用 `services.GetConfiguration()`，不临时构建容器。
- 默认使用测试内存 sink，移除默认 Seq 发送及固定 `D:\` 文件输出。
- 日志实例由测试宿主管理和释放，移除静态全局 Logger 与 `ProcessExit` 释放逻辑。
- 保留现有日志调用覆盖，并补充实际日志事件、参数、级别和上下文断言；文件输出使用单独测试、临时目录，关闭 logger 后清理。
- 保留生产侧“注册期不能解析委托或类型注册”的约束。

### T04：修复取消传播并稳定退避验证

**AOP：**

- 先增加确定性回归，分别覆盖调用时已经取消、通过信号控制的异步取消；同时验证异常传播、提交次数为零、提交后回调未执行。
- 对照当前 AspectCore 3.0.0 对应源码核对快速完成路径：其调用器检查 Faulted 和 Completed，却未显式处理已经 Canceled 的调用；目标取消时，返回值也可能尚未赋值。这是当前修复假设，必须由新增用例确认。[对应源码](https://github.com/dotnetcore/AspectCore-Framework/blob/d6be7102275e5215872193b6a175b34db28063e5/src/AspectCore.Core/DynamicProxy/AspectActivator.cs)
- 在现有 Uow 拦截器内增加局部取消兼容处理，使异步返回值保留可观察的取消异常与令牌，再向上传播；覆盖 Task、Task<T>、ValueTask 和 ValueTask<T>，避免重复消费 ValueTask。
- 不升级或复制 AspectCore，不替换全局代理机制，不通过改变测试期待来接受取消丢失。

**EventBus：**

- 用线程安全记录器保存每次构造尝试的单调时钟时间，通过信号等待三次尝试。
- 停止宿主后，断言相邻尝试满足当前至少 100 毫秒的退避要求，且业务处理未执行。
- 移除“等待 250 毫秒后最多四次”的断言；使用 10 秒截止时间等待进展，停止宿主另设 5 秒截止时间。
- 先只修改测试；仅当新证据证明生产退避不满足契约时修复生产逻辑。

## 3. 真实数据库验收

复用 `framework/tests/compose/sql-providers.compose.yml`，通过本任务专属 Compose project 和覆盖配置启动环境：

- 使用模板现有 MySQL 8.4、SQL Server 2022、PostgreSQL 16，记录实际镜像身份和数据库版本。
- 端口仅绑定回环地址并自动分配；不连接、停止或重置当前已运行的数据库容器。
- 创建本任务专用测试数据库；MySQL 另建跨库测试数据库并配置必要授权。仅对这些数据库启用现有 reset 安全许可。
- 就绪检查设置总截止时间并保存失败诊断；环境启动失败时记录阻塞，不循环延长等待。
- 通过现有 Provider runner，顺序执行 MySQL、SQL Server 的 net6/net8 Release 集成测试；MySQL 显式启用跨库场景。
- 单独运行三 Provider 混合测试，限定到原方法，仅在该子进程设置全局门控及三库连接。
- 按测试操作创建并释放 DI scope；修复此次真实验收暴露的根容器解析问题，scope 覆盖查询、枚举及对象释放全过程。
- 验收结束仅清理本任务创建的容器和数据资源，保留脱敏日志及 TRX。

数据库实际执行出现的新失败，先保留失败用例，再修复与本次验收直接相关的问题。

## 4. 验证顺序与通过标准

1. **精准回归**：配置选择、Logging、AOP 取消、EventBus 退避，均覆盖 net6/net8。
2. **受影响项目**：共享测试设施、Logging、AOP、EventBus 完整测试；涉及 SQL 生命周期时运行 SQLite 本地集成。
3. **真实数据库**：两个 Provider 的完整专项及三 Provider 混合用例；原失败清单中的数据库测试必须有实际通过证据。
4. **最终检查点**：重新构建 Release，在独立子进程关闭外部门控，执行：

   ```powershell
   dotnet test Bing.All.slnx -c Release --no-build --no-restore --logger trx
   ```

5. 执行文档一致性、UTF-8 和 `git diff --check`，汇总本轮各 TFM 的独立结果。

通过标准：

- 默认全量测试退出码为 0，失败数为 0。
- 原 181 项全部有明确闭环；数据库用例同时具有真实执行证据，不能仅靠默认跳过关闭。
- 其他外部服务的跳过项单列，不计为通过，不要求原有 869 项全部执行。
- 不使用自动重试掩盖失败、不放宽断言、不全局关闭并行测试。
- 全量测试只在最终候选检查点运行；后续无关文档修改复用已有证据。
