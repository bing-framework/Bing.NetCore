## 合并后的结论

- 逻辑键、前缀、模式和命名空间检查未配对 UTF-16 代理项；输入长度按 UTF-16 code unit 计算。NullCache 保持空结果适配器行为，仅补齐取消语义。
- List/Stream 保持顺序、重复键、缺失和 null-hit 区分。消费中取消阻止下一批派发，第二批异常保留已产出结果；已发送命令不承诺撤回。
- 批量响应超预算时递归二分重读，单值仍超限明确失败；不能限制客户端已接收的网络缓冲，也不提供跨键快照。
- 原生 Redis SCAN 计量候选键和扫描页；下一页前检查 MaxScanPages。自定义 EasyCaching Provider 可实现页流接口，旧隐藏分页回退不伪造页数。
- Cluster 按 hash slot 分组，客户端分片按 MaxConcurrency 分窗；同步分片清理默认 Sequential，BoundedParallel 必须显式选择。首错取消窗口并观察已派发任务。
- Hybrid 使用原子值/PTTL 读取、回填代次闸门与失效传播；已提交写删后的失效不受调用方取消令牌阻断。null 不回填内存层，失效消息按实际序列化字节拆分。
- 可选 outbox 提供 pending/processing 上限、有限重试、恢复、只读诊断和有界死信管理；默认关闭。死信支持保留期、payload 字节预算、授权查看/重放/确认删除及审计。
- 099 的 handle/payload 分离与惰性迁移实现已存在，跨版本发布验证仍未完成；新版格式不能直接声称兼容旧二进制。

正式批量读/扫描 P95 与分配预算仍为已验证失败边界，100,000 项超时单元不补造统计。严格三方同构基线缺中间源码；真实网络往返、客户端队列与跨进程全局指标延后。NullCache 是否输出逐键 miss 仍待行为审批。Redis 数据提交到失效入队之间的崩溃窗口、SCAN/Clear 非原子、批量部分成功、实际 Redis allocator 内存预算均保留现有边界。
