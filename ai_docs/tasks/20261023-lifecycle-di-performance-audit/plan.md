# GC、依赖注入、释放与性能专项复查

任务：20261023-lifecycle-di-performance-audit。

用户要求再次检查当前功能是否存在 GC、性能、DI 和资源释放问题。本轮为检查与建议，产出审查报告及必要的最小复现；不修改生产实现，不重新启动旧任务的 Fix 循环。

## 范围

1. 模块生命周期：当前工厂缓存修复、应用注册与释放、静态/异步引用链、取消及异常退出。GC 调查沿用用户指定 Codex GPT-6-Astra/xhigh。
2. 业务生命周期：Uow 自动边界、operation executor、AsyncLocal、Dapper/EF 工厂与连接/事务/reader 所有权，CAP runtime 及后台 scope 的邻接路径。
3. 性能与长期运行：缓存增长、可释放 Transient 的容器保留、重复分配/解析、同步等待、异常路径资源释放，结合已有有界 probe 和真实执行证据。
4. 汇总确认缺陷、可执行修复建议、已验证能力及限制。这里的“漏洞”重点指生命周期正确性与资源风险，不等于全产品安全渗透验收。

## 方法与通过条件

- 读取当前真实源码、注册和调用链、测试与原始证据；不以 PASS 报告替代实现分析。
- 复用刚完成的最终候选 Release/default suite：12,894 Passed / 0 Failed / 1,114 NotExecuted。核对相关源范围未变；本轮不为重复确认绿色运行全量。
- 已关闭 GC 机制不无因重新打开；新的疑点必须有具体触发条件、对象/资源持有链与源码位置。永久泄漏、临时引用保留、正常 scope 所有权分别判断。
- 需要运行新复现时先写简洁 CIA、固定输入及截止；仅在任务 artifacts 内添加独立探针，不修改既有断言、生产源码和历史 raw。未有证据不宣称缺陷，不以压力矩阵替代推理。
- 性能没有正式预算时仅报告测量范围和风险，不批准阈值；没有相关热路径变化不重复完整基线。
- 每个确认问题给出优先级、影响、证据、建议修改及验收方式；已接受限制和外部未验证项独立列出。
