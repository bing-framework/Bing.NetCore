# 集群事件、一致性与运行治理完善计划

本任务执行用户在当前会话批准的同名五阶段计划。验收范围是九组能力：本地/分布式事件、CAP 事务消息、集群事件边界、限流、审计、双平台蓝绿、RabbitMQ 按实体有序、库存并发、进程内原子工具。

## 阶段顺序

1. P0 修复本地/Redis 锁的原子性、所有者校验、异步释放及订阅并发快照，并以真实 Redis 和并发测试验收。
2. P1 将 CAP 与事件事务生命周期闭环，提供元数据和同事务业务幂等；旧事件契约继续兼容。
3. P2 建立按实体连续序号、持久化游标、失败恢复和两套 ORM 的条件扣库存，使用 MySQL 双实例验证。
4. P3 建立本地/Redis 令牌桶与 HTTP 接入、分级审计、进程内原子工具。
5. P4 提供 Compose/Nginx、Kubernetes 双平台蓝绿流程，并完成宿主角色、就绪、排空和动态验证。

## 不变量

- 库存由数据库条件更新、唯一键和事务保证；Redis 锁不作为唯一正确性基础。
- CAP 至少一次投递；业务消费幂等和顺序在同一数据库事务内维护。
- 本地事件不跨节点；消费者组与业务幂等键在蓝绿版本间保持稳定。
- 普通审计可告警，关键审计失败应使业务回滚；默认不记录敏感正文。
- 强杀进程时不承诺执行托管释放；超时不能误报资源已清理。
- 保持当前目标框架、依赖与 `global.json`，实际 SDK 与锁定 SDK 分开记录。
