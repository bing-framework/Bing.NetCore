# 缓存批量路径性能优化与流式能力计划

本任务执行用户批准的缓存批量路径性能优化计划，范围覆盖 Bing.Caching 公共契约、FreeRedis、CSRedis、EasyCaching Redis/Hybrid、精准测试、性能探针和执行报告。

## 目标

- 新增 `CacheEntry<T>` 与批量读取/前缀扫描异步流 API，同时保持现有 List API 的顺序、重复键和缺失语义。
- 优化三个 Provider 的批量读取、扫描、取消和内存分配路径，保持命名空间、拓扑、租约和 Hybrid 最终一致语义。
- 补充公共契约、Provider、取消、分片/Cluster、Hybrid 一致性测试。
- 扩展性能探针并记录旧版、当前版、优化版证据；不自行批准性能预算。

## 验收

- 受影响项目可编译，精准测试和适用的完整测试有明确结果。
- `netstandard2.0` 公共项目保留目标框架并正确提供异步枚举依赖。
- `git diff --check` 通过，execution.md、performance.md、生产符号到测试方法映射和独立 review.md 完整。
- 性能预算按用户计划记录：批量读/扫描 P95 回退不超过 20%，分配量不超过 30%，命中读 P95 不超过 10%；未达或无法验证的项目标记为相应阻塞/TODO，不伪造通过。

## 非目标

- 不修改 SQL 内部缓存、旧内存管理器、命名空间/物理键格式、租约语义或 Provider 注册方式。
- 不自动提交、推送、发布或批准性能回退预算。
