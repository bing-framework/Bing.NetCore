# 缓存性能 TODO：FreeRedis 单节点批量路由分配

## 目标

处理性能审查 FIX-007 中尚未尝试的结构性根因：FreeRedis 在单节点批量读取时仍执行客户端分组、索引列表建立和二次键数组复制。单节点不需要路由分组，应直接把已生成的物理键批次交给同一客户端。

## 实现范围

- 优化 FreeRedis 的异步流式批量读取和前缀扫描批读取单节点路径。
- 同步 `GetAll`/前缀读取也移除单节点的无用分组层，保持 Cluster/客户端分片分组逻辑不变。
- 让解码方法同时支持“原顺序批次”和“带索引分组批次”。
- 保留命名空间、键格式、批大小、字节预算、取消和租约语义。

## 验证

- 先构建 `Bing.Caching.FreeRedis`。
- 运行 FreeRedis 批量契约和协调精准测试（门控关闭时记录跳过；本轮使用已有本地 Redis 时启用门控）。
- 运行 FreeRedis 单节点短基准，记录当前候选绝对指标；不把不同探针或不同源码的结果伪装成严格 before/after。
- `git diff --check`，更新本任务 `execution.md`、`TODO.md` 和生产符号映射。

## 非目标

- 不再次尝试已停止的 SHA/键编码、MGET 返回类型或 JSON 拼接微调。
- 不调整性能预算，不修改 Cluster/分片路由，不执行 Redis 管理清理命令。
