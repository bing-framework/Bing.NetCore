# 缓存性能对照

## 基准身份与方法

- 旧版提交：`24c93cb1a5355797223637e2d42ac3dce968d7ef`。
- 旧版 FreeRedis 源 Blob：`26ca707089da1acbb658e220c15a2747f5e3ff08`；CSRedis 源 Blob：`9d2b0fcf49c628d92a28ce02b0d2da0e0d1f2e75`。
- 运行时：.NET 8.0.30；同一机器、同一本机隔离 Redis 7 容器，单节点，端口 52782。
- 同一份 `bench/Program.cs` 分别编译旧版与候选实现。每个 Provider、每个键数独立运行：1 千项 10 轮，1 万项 5 轮；每轮依次写入、100 次命中读、批量读取、按前缀扫描、16 路同键回源、删除。
- 旧版用唯一键前缀隔离运行，候选版用唯一 `CacheConfiguration.Namespace` 隔离；两者逻辑项数及调用顺序一致。候选版物理键包含版本、命名空间和键级 hash tag，因此键长度不是相同字节数。此差异是新契约的实际成本。
- P50/P95/P99 使用轮次或命中读样本的最近秩分位数。批量阶段只有 5 或 10 个样本，P99 仅作描述，不作为发布阈值。
- Redis 命令数读取 `INFO stats.total_commands_processed`，包含 Lua 脚本内部执行的命令，不等于网络往返数。采集时未并发运行其他基准；进程分配量使用 `GC.GetTotalAllocatedBytes(true)`，峰值内存使用进程 `PeakWorkingSet64`。

候选版两 Provider 均消除了正常条件下的同键重复回源；它同时引入键隔离、租约及原子提交。批量读取、扫描及分配量未表现出提升。CSRedis 写入通过 Lua 保留毫秒 TTL，Redis 统计对每项同时计入 `EVAL` 和内部 `SET`，解释了约每千项增加千条服务器命令；其批量读阶段约为 2 条服务器命令。旧版没有可比较的命名空间隔离或失租拒写能力，这些能力不计算提升比例。

结构验收仍成立：FreeRedis/CSRedis 非 Cluster 批量读使用有限大小的多键命令；Cluster 按单键跨槽执行并限制在途数；扫描逐页处理。不能依据本轮单机结果宣称整体吞吐或内存优化。
