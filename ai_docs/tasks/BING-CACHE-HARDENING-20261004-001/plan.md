# 缓存模块审计、修复与优化计划

## 目标与范围

覆盖 Bing.Caching、FreeRedis、CSRedis、EasyCaching 和 Bing.Core 当前有效的集合缓存；不修改 SQL 内部缓存，不恢复已注释的旧内存管理器。用户允许必要的破坏性重构，并确认强制命名空间、集群与分片、跨进程回源协调及缓存级非严格一次保证。

## 当前实现与证据

- 两个 Redis 适配器已提供 ICache 同步/异步基础操作，但 `Clear` 使用 FLUSHDB，前缀与模式检查可被 `**` 绕过；扫描累积全部键，异步路径混用同步扫描。
- FreeRedis `SetAllAsync` 使用 NX，无法覆盖旧值；异步 TTL 转整秒，丢失亚秒精度。
- 两个 Redis 的回源路径都是 Exists/Get/工厂/Set，没有并发协调；缺少集群/分片职责级测试。
- EasyCaching 注册入口被注释、构造函数清空进程级配置，Hybrid 部分方法绕过 Hybrid Provider；当前功能仅部分可用。
- Bing.Core 的有效集合缓存暴露内部可变容器，读写检查不在同一锁中；旧 InMemoryCacheManager 整段注释，不是当前运行时能力。
- 基线测试项目缺少 project.assets.json；测试尚未执行。整体为部分实现，发布前需要正确性、集成和性能证据。

## Phase 1：公共契约与隔离

### P1 配置与键

- 目标：为每个缓存实例增加必填命名空间、Provider 名称、默认 TTL、批量与协调参数；统一版本化物理键，禁止隐藏客户端前缀。
- 现状/证据：静态 RedisHelper 和 CachingOptions；普通键没有命名空间。
- 修改范围：Bing.Caching 公共配置/键、两个 Redis 适配器、EasyCaching DI/admin 注册。
- 步骤：定义不可变选项与键编码；各实现统一转换；DI 负责客户端生命周期；旧键不回读，迁移说明冷缓存。
- 依赖：无。验证：键、选项、DI 直接测试。风险：公开构造方式和物理键变化。验收：不同命名空间互不影响。

### P2 行为契约

- 目标：统一覆盖写、原子 TrySet、毫秒 TTL、命中/未命中、批量顺序、前缀和模式语义。
- 现状/证据：FreeRedis 异步写与 TTL 不一致，Get 回源多余 Exists。
- 修改范围：ICache 扩展重载、适配器及契约测试。
- 步骤：新增带 CancellationToken 的异步回源重载；统一输入与 TTL 校验；保留旧签名转发。
- 依赖：P1。验证：两个 Provider 的同一契约测试。风险：参数校验变严格。验收：null/default、重复键、空批次、非法 TTL 一致。

## Phase 2：Redis 正确性、拓扑与性能

### P3 有界操作与安全清理

- 目标：修复批量覆盖、异步 I/O、取消、前缀/模式隔离和 FLUSHDB。
- 现状/证据：同步 Scan、大数组 MGET/DEL、无界 Task.WhenAll、Clear 清全库。
- 修改范围：两个 Redis 适配器及直接测试。
- 步骤：每批默认 500、并发默认 8；逐批扫描处理；Clear 只处理命名空间；失败显式传播。
- 依赖：P1/P2。验证：两个命名空间哨兵键、1k/10k 批量、取消与失败测试。风险：扫描期间并发写入不保证原子清空。验收：无整库清理、无无界任务或全量键集合。

### P4 集群/分片

- 目标：单节点、Cluster、客户端分片正确路由。
- 现状/证据：当前扫描仅一个游标，跨槽批量未验证。
- 修改范围：拓扑适配与集成环境。
- 步骤：扫描所有主节点/分片；多键按槽或节点分组；数据/租约键同槽，键级 hash tag 分散不同数据键；重定向失败显式报错。
- 依赖：P3。验证：单节点、三主三从 Cluster、双节点分片，故障转移。风险：旧客户端 API 能力需以实际包/集成测试确认。验收：跨节点键完整且不发生 CROSSSLOT。

### P5 跨进程回源

- 目标：减轻热点击穿，失去租约后禁止旧请求写回。
- 现状/证据：Exists/Get/回源/Set 竞争。
- 修改范围：Redis 适配器、共享协调契约与集成测试。
- 步骤：进程内同键合并；SET NX PX 随机令牌；获取后重读；带抖动等待；令牌校验续租/释放和同槽原子提交；默认租约 30s、续租 10s、等待 30s、总限 2min；协调失败抛错。
- 依赖：P4。验证：双进程、异常、超时、取消、租约丢失、递归回源。风险：Redis 故障转移不保证严格一次执行；回源必须幂等。验收：正常状态同键合并，旧持有者不能覆盖新值。

## Phase 3：接入、Core 与交付

### P6 EasyCaching

- 目标：恢复 Memory/Redis/Hybrid DI，并修复静态状态及混合缓存操作一致性。
- 现状/证据：AddCaching 被注释、构造时 Clear，部分方法绕过 Hybrid。
- 修改范围：Bing.EasyCaching 与对应测试。
- 步骤：显式注册命名 Provider；内存回源合并；Redis/Hybrid 使用共享协调；Hybrid 变更同时处理本地层和跨实例失效，传播失败须报告。
- 依赖：P1/P5。验证：独立单元和多实例集成测试。风险：EasyCaching API/序列化与原子脚本适配。验收：三种模式走真实主调用链。

### P7 Core 集合缓存

- 目标：原子检查修改、快照 Reader、准确返回值。
- 现状/证据：锁外检查，Reader 直接返回内部集合。
- 修改范围：两个有效缓存基类和 Bing.Core.Tests。
- 步骤：锁内检查/读写；Reader 返回浅快照；批量删除返回是否至少删除一项；列表保序。
- 依赖：无。验证：并发、快照、失败与重复键直接测试。风险：Reader 从实时视图变成快照。验收：无重复添加或外部直接修改。

### P8-P9 验证、性能和文档

- 目标：迁移 admin 接入，形成职责级测试、性能基线、追溯与执行报告。
- 步骤：先 L0/L1，再受影响项目 net6/net8 测试、netstandard2.0 构建；外部 Redis 继续 RUN_INTEGRATION_TESTS 门控。基线冻结一次，测命中、并发回源、1k/10k 批量、扫描的吞吐、延迟、命令数、分配和峰值内存；最终维护生产符号到测试方法映射。
- 依赖：P1-P7。验证：git diff --check、受影响依赖构建、单/多节点集成及基准证据。风险：缺少隔离多节点环境时分类 BLOCKED_EXTERNAL，不用单节点伪装通过。验收：完成代码、测试、迁移文档、execution.md 与独立 review.md。
