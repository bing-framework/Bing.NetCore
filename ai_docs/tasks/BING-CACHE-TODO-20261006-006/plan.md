# 缓存 TODO 续作：隔离 Redis 协调证据

## 目标

在上一轮已完成生产实现的基础上，使用本机已确认的 Redis 单节点测试环境补齐可执行的真实证据：

1. 运行 FreeRedis、CSRedis 的首批取消命令计数测试。
2. 运行独立进程探针，覆盖同键合并、持有者异常退出接管、超时旧回源拒写、失租拒写和等待超时。
3. 运行 EasyCaching Redis/Hybrid 的协调、显式写删撤销和跨实例失效测试中可由单节点环境支持的部分。
4. 更新本轮 TODO、执行报告和生产符号到测试方法映射，明确未能验证的基线、集群和独立总线能力。

## 范围

- `framework/tests/Bing.Caching.ProcessProbe` 及 FreeRedis/CSRedis/EasyCaching 集成测试门控。
- 仅使用随机命名空间和测试数据；不执行 `FLUSHDB`，不触碰现有数据库中的哨兵键。
- 若测试揭示当前源码中的可修复问题，只修改对应最小范围并补精准测试。

## 验收

- 实际 Redis 连接、测试命令、目标框架和通过/跳过结果可追溯记录。
- 进程探针所有声明的场景通过，或将失败明确归类为代码问题/环境阻塞。
- 单节点证据不替代 Cluster、客户端分片、独立总线和历史 baseline 证据。
- 不自动提交、推送、发布或放宽性能预算。

## 非目标

- 不恢复历史 baseline checkout，不伪造性能对照结果。
- 不创建或启动 Docker/集群，不执行破坏性 Redis 管理命令。
