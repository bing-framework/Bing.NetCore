# 缓存基准检查点与流式契约补齐计划

## 目标

继续实现上一轮 TODO 中仍可在仓库内闭环的两项能力：

1. 基准工具按规模、按样本安全保存检查点，并记录数据集身份，避免整轮超时丢失已完成统计或把残留键误认为当前数据集。
2. 补齐流式 API 的取消、特殊前缀和部分失败测试证据，验证取消后不继续派发命令，且已产出结果与后续异常语义明确。

## 范围

- `ai_docs/tasks/BING-CACHE-PERF-STREAM-20261004-002/bench/Program.cs` 及其 README。
- FreeRedis、CSRedis、EasyCaching 现有精准测试文件。
- 本任务文档、执行报告和 TODO 状态。

## 实现要求

- 基准输出仍保持现有最终 JSON 格式兼容。
- 每个规模完成一个样本后原子写入 checkpoint；进程异常或超时不覆盖已完成 checkpoint。
- checkpoint 包含任务标签、Provider、拓扑、端点摘要、规模、已完成 warmup/sample 数、命名空间/数据集标识和原始样本。
- 不把 checkpoint 当作完整正式报告；只有完成该规模全部样本才加入最终 Results。
- 测试只使用现有隔离门控和已有命令监控，不修改生产缓存实现。

## 验证

- 运行基准工程 `dotnet build --no-restore` 或等价最小构建。
- 运行新增/受影响流式精准测试；缺少 Redis 环境时保留门控状态，不伪造通过。
- UTF-8、`git diff --check`，并更新 `execution.md`、`TODO.md`。

## 非目标

- 不重跑已达到边界的完整性能矩阵。
- 不处理需要外部中间源码或真实网络客户端内部计数器的 TODO。
- 不调整既有性能预算，不提交、推送或发布。
