# Bing.NetCore 设计思路文档

> **适用版本**：框架 `7.0.0`（`version.props`）｜ 目标框架：类库 `netstandard2.0`、Web / 应用 `net6.0`｜ 内容核对：2026-09-18｜ 版本历史见 [发行说明](../ReleaseNotes.md)

> 面向后续使用者与维护者：本文阐述 Bing.NetCore 的整体架构、模块划分、关键设计决策及其权衡、数据流与扩展方式，帮助你在理解“为什么这样设计”的基础上安全地上手与演进框架。内容与 `framework/src`、`modules`、`samples` 中的真实代码保持一致。
>
> 配套文档：《使用文档》——安装配置与上手示例（含 §3.3 注册入口速查）；《架构文档》——分层结构、模块依赖图与注册入口完整清单（§12）；《子系统深挖文档》——CAP / FreeSQL / Bing.Data.Sql 代码级解析。

---

## 1. 设计目标与定位

| 目标 | 说明 |
| --- | --- |
| 提升交付效率 | 用现成的分层基类与横切能力，让团队聚焦业务领域建模 |
| 约定优于配置 | 通过标记接口自动注册、模块引导，减少样板代码 |
| 多 ORM 并存 | 同一套领域抽象可挂 EF Core / FreeSQL / Dapper，按需替换 |
| 模块化可插拔 | 以 `BingModule` 为单元组织能力，依赖图自动解析与排序 |
| 统一体验 | Web 统一响应、统一异常、统一当前用户/租户抽象 |

框架借鉴了 ABP 的模块化思想、Util/Nop 的基础代码组织方式，但落在 .NET 平台的自研实现上。

## 3. 模块划分

`framework/src` 下的工程按职责分组：

| 分组 | 工程 | 职责 |
| --- | --- | --- |
| 核心地基 | `Bing.Core` | 模块系统、约定式 DI、反射查找、异常体系、时钟、选项、类型/程序集查找器 |
| 横切基础 | `Bing.Uow` `Bing.Validation` `Bing.ObjectMapping` `Bing.Localization` `Bing.Security` `Bing.Permissions` `Bing.Auditing` `Bing.ExceptionHandling` `Bing.MultiTenancy` | 工作单元、验证、映射、本地化、安全/权限、审计、异常、多租户 |

| ORM 实现 | `Bing.EntityFrameworkCore*` `Bing.FreeSQL*` `Bing.Dapper.*` | 各 ORM 的仓储/工作单元实现与多数据库 Provider |
| Web | `Bing.AspNetCore` `Bing.AspNetCore.Abstractions` `Bing.AspNetCore.Mvc` `Bing.AspNetCore.Mvc.Contracts` `Bing.AspNetCore.Mvc.UI` `Bing.AspNetCore.Serilog` `Bing.AspNetCore.MultiTenancy` `Bing.AspNetCore.Authentication.JwtBearer` `Bing.MiniProfiler` | 模块化管道、控制器基类、统一响应、JWT、多租户、Serilog 增强、MiniProfiler |
| AOP | `Bing.Aop.AspectCore` | 基于 AspectCore 的拦截器、属性注入、参数校验 |
| 缓存 | `Bing.Caching` `Bing.Caching.CSRedis` `Bing.Caching.FreeRedis` `Bing.EasyCaching` | 缓存抽象与 Redis/EasyCaching 提供器 |
| 日志 | `Bing.Logging` `Bing.Logging.Serilog` `Bing.Logging.Sinks.Exceptionless` | 日志抽象、Serilog 增强、Exceptionless Sink |
| 事件 | `Bing.EventBus` `Bing.EventBus.Abstractions` `Bing.Events` `Bing.Events.Cap.MySql` | 本地/分布式事件总线、CAP 集成、MySQL 存储 |
| 其他业务 | `Bing.Emailing` `Bing.MailKit` `Bing.TextTemplating` `Bing.TextTemplating.Scriban` `Bing.Locks.CSRedis` | 邮件、文本模板（Scriban）、分布式锁 |

## 4. 关键设计决策与权衡

### 4.1 模块化两阶段启动（Module System）

- **决策**：以 `BingModule`（`AddServices` + `UseModule`）为单元，配合 `[DependsOnModule]` 与 `ModuleLevel` 排序，替代“在 `Startup.ConfigureServices/Configure` 里手写一长串注册”的传统方式。入口为 `services.AddBing().AddModule<T>()` 与 `app.UseBing()`。
- **权衡**：模块可插拔、依赖自动解析，团队可按能力裁剪（如只加 `LogModule` / `CacheModule`）。代价是“启动逻辑分散到各模块”，需要熟悉模块依赖图；另外保存了一个全局 `IServiceProvider.UseBing()` 重载以支持非 Web 场景。

### 4.2 约定式 DI 自动注册

- **决策**：实现 `ISingletonDependency` / `IScopedDependency` / `ITransientDependency` 的类型由 `DependencyModule`（`Level=Core`）扫描并注册；`[Dependency(...)]` 控制生命周期与替换策略；接口基类型用 `[IgnoreDependency]` 排除。
- **权衡**：大幅减少样板注册代码，且新类“加了标记即被注入”。代价是启动期有一次程序集扫描（对超大应用可能有毫秒级开销，框架用 `AssemblyManager` 做缓存缓解）；生命周期不直观时排查稍难，故提供 `TryAdd` / `ReplaceExisting` 显式覆盖。

### 4.3 多 ORM 后端并存 + 共享领域抽象

- **决策**：`IRepository` / `IStore` / `IQueryStore` / `IUnitOfWork` 定义于 `Bing.Ddd.Domain`（与 ORM 无关）；EF Core、FreeSQL、Dapper 各自实现。`Bing.Data.Sql` 作为“通用 SQL 引擎”，被三者复用（EF 经 `IEfCoreSqlQueryFactory`、FreeSQL 直接用 `ISqlQuery`、Dapper 直接落地执行器）。
- **权衡**：业务代码只依赖领域接口，可在不改动应用层的情况下替换 ORM；流利 SQL 引擎统一了跨库方言。代价是抽象层较多，EF 的运行时命名空间为 `Bing.Datas.EntityFramework.Core`（与包名 `Bing.EntityFrameworkCore` 不一致，需注意）；FreeSQL 当前仅 MySql Provider；Dapper 不提供仓储/工作单元，需自建或配合 `ISqlQuery`。

### 4.4 统一 API 响应（结果过滤器）

- **决策**：用全局 `ResultHandlerAttribute`（ASP.NET 结果过滤器）把任意 Action 返回值包成 `ApiResult{ Code, Message, Data, OperationTime }`；`[IgnoreResultHandler]` 提供退出点；`IResultFactory` 允许替换结果形状。
- **权衡**：业务控制器无需关心包装细节，统一成功/失败结构。代价是“全局拦截”对需要返回非标准结构（如文件流、原始 `IActionResult`）的 Action 需显式跳过；因此 `IRemoteStreamContent` 等通过 `BingMvcOptionsExtensions.AddBing` 走专用格式化器。

### 4.5 工作单元与 AOP 自动提交

- **决策**：`IUnitOfWork.Commit/CommitAsync` 为提交边界；`[UnitOfWork]`（基于 AspectCore 的 `InterceptorBase`）在应用服务方法成功后由 `IUnitOfWorkManager.CommitAsync()` 统一提交；`CrudAppServiceBase` 已内置该特性。也可显式 `UnitOfWork.CommitAsync()`。
- **权衡**：避免“忘记提交”的常见错误，事务边界清晰。代价是 AOP 代理对 `EF DbContext`、`[IgnoreAspect]` 接口默认不代理，避免自我代理导致的问题；需要属性注入时控制器要 `AddControllersAsServices()`。

### 4.6 多租户解析链

- **决策**：`ITenantResolveContributor` 链（`CurrentUser` → `Header` / `QueryString` / `Route` / `Domain` / `Cookie`）；`MultiTenancyMiddleware` 用 `ICurrentTenant.Change(id, name)` 在请求内切换。
- **权衡**：解析策略可组合、顺序可调，且基于 `AsyncLocal` 作用域隔离。代价是仓库未提供 `UseMultiTenancy` 便捷扩展，需手动 `app.UseMiddleware<MultiTenancyMiddleware>()` 并配置 `BingTenantResolveOptions.TenantResolvers`（这是刻意的“不过度封装”，让使用者明确解析链）。

### 4.7 横切能力“靠约定自动注册”

- **决策**：缓存、日志、事件、邮件、模板、锁、映射、本地化、异常等大部分能力**没有** `AddXxx` 帮助方法，而是靠 `ITransientDependency` / `IScopedDependency` 自动注册 + `Options` 类配置（如 `BingTextTemplatingOptions`、缓存用 `RedisHelper.Initialization` + `AddScoped<ICache, ...>`）。
- **权衡**：与 4.2 的约定一致，减少记忆负担；少数确需显式初始化的（如 CSRedis 静态 `RedisHelper`）保留手动步骤。例外是有明确注册方法的：`AddBingLogging`、`AddDefaultEventBus` / `AddCapEventBus`、`AddSmtpEmail` / `AddMailKit`、`AddRedisDistributedLock`、`AddAutoMapper`、`AddJwt`、`EnableAop`。

### 4.8 异常体系与统一错误

- **决策**：`Bing.Core` 定义 `Warning` / `BusinessException` / `UserFriendlyException`（实现 `IHasErrorCode` / `IHasHttpStatusCode` 等标记接口）；`Bing.ExceptionHandling` 的 `DefaultExceptionToErrorInfoConverter` 识别异常类型生成错误码与提示；Web 层用中间件 + `BingExceptionFilter` 输出 `{ code, message }`。
- **权衡**：业务层用语义化异常（如 `throw new BusinessException("1001","余额不足")`）即可获得统一错误响应，且生产环境默认不暴露堆栈（由 `BingExceptionHandlingOptions` 控制）。

### 4.9 双目标框架（netstandard2.0 vs net6.0）

- **决策**：类库默认 `netstandard2.0`（最大化可复用性，可被 net framework / net core 引用）；与 ASP.NET Core 强耦合或依赖 EF Core 6 / CAP 8 的工程覆盖为 `net6.0`（如 `Bing.AspNetCore.*`、`Bing.Permissions`、`Bing.Events`），`Bing.Events.Cap.MySql` 为 `netstandard2.1`。
- **权衡**：库的可移植性 vs 使用新框架特性的能力；演进时需注意“新增仅 net6.0 可用的能力”会抬升消费者的最低版本。

### 4.10 Roslyn 源生成器减样板

- **决策**：`Bing.Ddd.Domain.Extensions.Analyzers` 在编译期为 `partial` 领域类自动生成 `AddChanges(TOther)`（变更跟踪对比），跳过 `Version` / `IsDeleted`；`Bing.Data.Sql.Analyzers` 提供 API 迁移诊断。
- **权衡**：用编译期代码生成消除重复的变更对比样板，且运行期零依赖；代价是调试时需理解生成的代码，且分析器须随包以 `analyzers\dotnet\cs` 形式发布。

## 5. 数据流

### 5.1 写请求（创建/更新，含事务提交）

```
HTTP 请求
  → MultiTenancyMiddleware（解析租户，ICurrentTenant.Change）
  → Authentication（JWT，填充 ClaimsPrincipal）
  → Controller(Action)  [ApiControllerBase]
      调用 ApplicationService 方法
        → Request.MapTo<Entity>()              （Bing.ObjectMapping + AutoMapper）
        → entity.Init()                         （生成主键 / 审计初始化）
        → IRepository/IStore.AddAsync(entity)   （领域接口，基础设施实现）
        → [UnitOfWork] 拦截器 或 UnitOfWork.CommitAsync()
             → UnitOfWorkBase.SaveChangesAsync   （EF: DbContext / FreeSQL: DbContext）
                 ├─ 软删除全局过滤、IVersion 乐观锁、审计字段注入
                 ├─ 派发聚合根领域事件（IDomainEventDispatcher）
                 └─ 与 CAP 集成的事务提交（如 AdminUnitOfWork）
  → ResultHandlerAttribute 包装为 ApiResult
  → 返回 { Code, Message, Data }
```

### 5.2 读请求（查询）

```
Controller(Action) → QueryAppServiceBase.PagerQueryAsync(queryParameter)
  → _store.Find(predicate)  或  new Query<TEntity>().Where(...).OrderBy(...)
  → IAsyncQueryableExecuter 执行
  → PagerList<TDto>  （分页结果）
  → Dto = entity.MapTo<TDto>()
  → Success(result)
```

### 5.3 事件流

```
领域事件：AggregateRoot.AddDomainEvent(e)
  → 提交时 IDomainEventDispatcher 派发
      ├─ 本地：ILocalEventBus → ILocalEventHandler<T>  （内存）
      └─ 分布式（CAP）：IMessageEventBus → 消息队列（RabbitMQ 等）
           → 订阅方处理 + 落库（Bing.Events.Cap.MySql 提供 MySQL 存储）

应用层命令/查询（CQRS-lite）：ICommand/IQuery + ICommandHandler/IQueryHandler（契约在 Bing.Ddd.Application.Contracts）
```

### 5.4 异常流

```
throw Warning / BusinessException
  → BingExceptionHandlingMiddleware（管道级）或 BingExceptionFilter（Action 级）
  → IExceptionToErrorInfoConverter.Convert(...)
  → IHttpExceptionStatusCodeFinder 决定 HTTP 状态
  → 响应头 Bing-Error-Format: true + JSON { code, message }
```

## 6. 扩展方式

### 6.1 自定义模块

```csharp
[DependsOnModule(typeof(AspNetCoreModule))]
public class MyModule : AspNetCoreBingModule
{
    public override ModuleLevel Level => ModuleLevel.Business;
    public override IServiceCollection AddServices(IServiceCollection services) { /* 注册 */ return services; }
    public override void UseModule(IApplicationBuilder app) { /* 装配管道 */ }
}
// 在 Startup 中：services.AddBing().AddModule<MyModule>();
```

### 6.2 自定义仓储 / 工作单元

- 仓储接口放在领域层：`IApplicationRepository : ICompactRepository<Application>`（加业务查询方法）。
- 实现放在基础设施层：继承 `CompactRepositoryBase<Application, ApplicationPo>`（EF）或 `RepositoryBase`（FreeSQL），实现 `ToEntity` / `ToPo` 映射。
- 工作单元：继承对应 Provider 的 `XxxUnitOfWorkBase`（如 `MySqlUnitOfWorkBase`），覆写 `SaveChangesAsync` 接入 CAP 等。

### 6.3 自定义统一响应

实现 `IResultFactory : ISingletonDependency`，注册为单例；`Success/Fail` 将使用你的工厂产出（仍可保留 `ApiResult` 兼容结构）。

### 6.4 自定义异常转换

实现 `IExceptionToErrorInfoConverter`（或直接替换 `DefaultExceptionToErrorInfoConverter`），控制异常 → 错误码/提示的映射。

### 6.5 自定义本地化 / 模板引擎 / 缓存提供器

- 本地化：实现 `ILocalizedStore` → `AddStoreLocalization<TStore>()`；或 JSON 文件 `AddJsonLocalization()`。
- 模板：实现 `ITemplateRenderingEngine`（`Name` + `RenderAsync`），登记到 `BingTextTemplatingOptions.RenderingEngines["名称"]`，并把 `DefaultRenderingEngine` 指向它（Scriban 即此模式）。
- 缓存：实现 `ICache` / `IRedisCache`（如 `CSRedisCacheManager`），按约定注册到 `ICache`。

### 6.6 新增数据库提供程序（Dapper / SQL 引擎）

为 `Bing.Data.Sql` 增加新数据库支持需提供两块扩展点：

1. `IDialect` 实现（标识符引用符、参数前缀、分页语法、函数生成）—— 如 `SqlServerDialect` / `MySqlDialect`。
2. `ISqlProvider` 实现（执行画像）+ 连接工厂 + `ISqlDbParameterCustomizer` + `IDatabaseTypeConverter`，并在 `AddXxxProvider()` 中登记到 `ISqlProviderRuntime`。

EF Core / FreeSQL 新增库则对应新增 `Bing.EntityFrameworkCore.Xxx` / `Bing.FreeSQL.Xxx` 提供程序，复制 `AddXxxUnitOfWork` + `XxxUnitOfWorkBase` 模板。

### 6.7 自定义 AOP 行为

继承 `Bing.Aspects.InterceptorBase` 编写拦截器，用 `services.EnableAop(cfg => { ... })` 配置；用 `IAopProxy` 限制仅对显式标记的类型生成代理，或用 `[IgnoreAspect]` 排除。

## 7. 命名与目录约定

- 类库默认 `netstandard2.0`；Web/应用工程 `net6.0`（见 `framework.props` / 各 `.csproj`）。

- 命名空间大致等于工程名（`Bing.Core` → `Bing.*`，`Bing.AspNetCore.Mvc` → `Bing.AspNetCore.Mvc`），但注意 EF Core 运行期为 `Bing.Datas.EntityFramework.Core`。
- 文档/SQL/计划等集中在 `docs`；AI 工作流约定在 `AGENTS.md`（强制 UTF-8、SQL 测试门槛等）。

## 8. 与同类框架对比（要点）

| 维度 | Bing.NetCore | ABP vNext（参考对象） |
| --- | --- | --- |
| 启动范式 | `BingModule` + `[DependsOnModule]` + `AddBing/UseBing` | `AbpModule` + `[DependsOn]` + `ConfigureServices/OnApplicationInitialization` |
| 统一响应 | `ResultHandlerAttribute` + `ApiResult` + `IResultFactory` | 过滤器 + `IActionResult` 包装 |
| ORM | EF Core / FreeSQL / Dapper 三选，共享领域抽象 | 主要 EF Core |
| 事件 | 本地事件总线 + CAP | 本地事件总线 + 分布式（CAP / Rebus） |
| 约定 DI | 标记接口自动注册 | 类似（AutoRegister 约定） |
| 范围 | 偏“基础能力 + 分层基类”集合，包更细粒度 | 大而全的应用框架 |

Bing.NetCore 更强调“可裁剪的细粒度包 + 多 ORM 并存 + 流利 SQL 引擎”，适合需要灵活组合基础能力的团队；ABP 则提供更完整的端到端应用骨架。

## 9. 上手建议（给新使用者）

1. 先读 `samples/Bing.Samples.WebApi` 与 `modules/admin`，理解模块引导与分层。
2. 业务建模：实体继承 `AggregateRoot` / `FullAuditedAggregateRoot`；仓储接口放领域层，实现放 `*.Data.EFCore`。
3. 应用服务：优先 `CrudAppServiceBase`（标准化 CRUD），复杂逻辑用 `AppServiceBase` 手写。
4. 控制器：继承 `QueryControllerBase` / `CrudControllerBase`，返回 `Success(...)`。
5. 横切能力：按第 4.7 / 4.8 节用约定或显式 `AddXxx` 启用；异常用 `Warning` / `BusinessException`。
6. 需要统一响应以外的结构、或替换某能力时，走第 6 节的扩展点。
