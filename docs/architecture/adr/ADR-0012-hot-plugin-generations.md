# ADR-0012：可回收的插件代

- 状态：已实现；当前工作树。
- 日期：2026-09-28。
- 范围：`Bing.PluginRuntime` 的受信插件整组切换。

## 背景

启动期插件进入默认加载上下文，并把服务注册到宿主根 DI 容器。根容器和 Web 管道构建后不能移除其中的注册，也不能卸载默认上下文中的程序集。

## 决策

动态插件使用独立运行库，面向 `net6.0` 和 `net8.0`。每一代插件拥有独立的可回收 `AssemblyLoadContext`、模块图和服务容器。新代初始化成功后切换服务入口；旧代等待已开始的 `RunAsync` 回调结束，再逆序关闭模块、释放容器和请求卸载。候选代失败时旧代保持可用。

调用方通过 `RunAsync` 的短期作用域使用服务，宿主只公开不引用插件程序集的 ID 和版本快照。运行中的回调不能等待同一宿主重新加载或关闭。`Bing.Core` 与 DI 契约复用宿主程序集身份。原有 `AddBingApplication` 的默认加载上下文行为保持不变。

## 后果与边界

- 运行中切换以整组插件和整套服务容器为单位；跨插件依赖仍由清单和模块图排序。
- 插件服务不会被注入已构建的宿主根容器。Web 请求可以通过动态宿主分派服务调用；已装配的中间件不随插件代替换。
- `Unload` 只发起协作式卸载。外部保留插件对象、类型、程序集、线程、委托或静态引用会阻止实际回收；插件必须在关闭钩子中清理自身资源。
- 插件代码仍完全可信；此机制不提供沙箱、进程隔离或自动文件系统监控。
