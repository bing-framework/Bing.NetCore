## 1. 测试工程全貌

### 1.1 布局

```
framework/tests/                    ← 47 个测试工程目录
  <工程名>.Tests/                    ← 单元测试
  <工程名>.Tests.Integration/        ← 集成测试（成对出现）
Bing.Test.Shared/                   ← 共享测试库（断言、门控、基类）
Bing.TestShare/ Bing.TestShare.MySql/ ← 共享测试模型（TestConfig / Product / UnitOfWork）

tests/                              ← 根目录：不是主战场
  Bing.Tests.Samples/               ← 样例测试工程
  runsettings/*.runsettings.example ← 集成测试配置模板（MySql / Oracle / PostgreSQL / SqlServer）

components/tests/                   ← Bing.Biz.Payments.Tests（⚠ 不在 Bing.All.sln 里）
```

> ⚠ **唯一的解决方案是根目录的 `Bing.All.sln`**，但它只收录了 `framework/tests` 下 40 个工程。`components/tests/Bing.Biz.Payments.Tests` **不在其中**——跑全量时会漏掉它，改这个包的 alone 要单独 `dotnet test`。

### 1.2 技术栈

| 项 | 值 |
| --- | --- |
| 测试框架 | **xunit**（默认 V2；可用 `BingTestingXunitMode=V3` 切 V3） |
| 运行器 | VSTest |
| 断言 | **Shouldly**（不是 FluentAssertions） |
| Mock | Moq |
| 覆盖率 | coverlet.collector |
| 目标框架 | `net8.0;net6.0`（`framework.tests.props`） |

### 1.3 props 三兄弟

| 文件 | 作用 |
| --- | --- |
| `common.tests.props`（根） | 通用测试属性（旧包引用已注释，转为 import） |
| `framework.tests.props` | 指定 `TargetFrameworks=net8.0;net6.0`，提供 `BingTesting*` 开关 |
| `testshare.tests.props` | 标记 `BingTestingProjectType=TestShare`，**不引用 Test SDK / Runner / Coverlet**（纯库） |

新建测试工程，csproj 通常只需要一行：

```xml
<Import Project="..\..\..\framework.tests.props" />
```

可选：`EnableDITestPackages=false`、`RootNamespace`、非 CI 时条件挂 `RunSettingsFilePath`。

## 2. 快速开始：跑测试

```bash
# 单个测试工程
dotnet test framework/tests/<工程名>/<工程名>.csproj

# 全量（较慢）
dotnet test Bing.All.sln

# 按名字过滤（VSTest filter）
dotnet test framework/tests/<工程名>/<工程名>.csproj \
  --filter "FullyQualifiedName~SqlQueryApiContractTest"

# 多个条件的或关系
--filter "FullyQualifiedName~A|FullyQualifiedName~B"

# 指定目标框架
dotnet test framework/tests/<工程名>/<工程名>.csproj -f net8.0
```

> ⚠ **别写 `tests/<工程>`**——测试工程在 `framework/tests/` 下。这条路径曾在 CONTRIBUTING 里写错过，现已修正。

## 3. 集成测试门控变量

SQLite 集成测试**默认可跑**（无需任何环境变量）。外部数据库需要通过以下环境变量门控：

| 变量 | 粒度 / 作用 |
| --- | --- |
| `RUN_INTEGRATION_TESTS` | **全局**总开关 |
| `RUN_MYSQL_INTEGRATION_TESTS` / `RUN_POSTGRESQL_...` / `RUN_SQLSERVER_...` / `RUN_ORACLE_...` / `RUN_DORIS_...` | **按 Provider** 门控（变量名由 `{NORMALIZED}` 大写生成，`.` 与 `-` 去除） |
| `ConnectionStrings__<Provider>Connection` | 连接串（**双下划线**是环境变量的层级分隔符） |
| `ALLOW_DATABASE_RESET_FOR_TESTS` | 允许重置测试库（危险操作需显式放行） |
| `BING_INTEGRATION_MYSQL_CROSS_DATABASE` / `..._NAME` | MySQL 跨库测试开关与目标库名 |
| `ConnectionStrings__RedisConnection` | ⚠ Redis **不走** `RUN_*` 门控，用连接串是否配置来判定 |

> 详细的门控策略与安全约束（如不得使用生产数据库）见 [integration-testing.md](../testing/integration-testing.md)。
>
> 每个 Provider 工程里有 `integration.local.runsettings`（MySql / PgSql / SqlServer / Sqlite），根目录 `tests/runsettings/` 提供 4 个 `.example` 模板。csproj 在非 CI 环境下会条件挂载 `RunSettingsFilePath`。

## 4. 怎么写单元测试

以 `framework/tests/Bing.Core.Tests` 为例：

```
Bing.Core.Tests/
  Bing.Core.Tests.csproj     ← import framework.tests.props
  global-usings.cs           ← 全局 using（Shouldly / Xunit 等）
  <按域分目录>/<目标>Test.cs   ← 测试类
```

断言用 Shouldly 风格：

```csharp
[Fact]
public void Should_GetSum()
{
    var result = Calculator.Sum(1, 2);
    result.ShouldBe(3);              // 不是 Assert.Equal(3, result)
}
```

单元测试工程一般**不需要 TestBase**，直接 `[Fact]` 即可。

## 5. 怎么写集成测试

以 `Bing.Dapper.Sqlite.Tests.Integration`（最完整的模板）为例：

```
Bing.Dapper.Sqlite.Tests.Integration/
  Bing.Dapper.Sqlite.Tests.Integration.csproj
  global-usings.cs
  Infrastructure/
    SqliteIntegrationDatabaseFixture.cs    ← 建临时库、种子数据
    SqliteIntegrationDatabaseCollection.cs ← xunit collection（共享 Fixture）
    StructuredTableSample.cs / AritySamples.cs  ← 测试用表模型
  SqlQuery/
    SqliteExecutionIntegrationTest.cs      ← 测试本体
  integration.local.runsettings
```

SQLite 的测试类是裸 `[Fact]`（因为它默认就能跑）；**外部数据库的测试类要用 `[IntegrationFact]`**（来自 `Bing.Test.Shared`），未开对应环境变量时会跳过而不是失败。

需要 ASP.NET Core DI 的集成测试（如 `Bing.Dapper.SqlServer.Tests.Integration`）额外多三样：

```xml
<XunitStartupFullName>Bing.Dapper.Tests.Startup</XunitStartupFullName>
<BingTestingUseXunitDependencyInjection>true</BingTestingUseXunitDependencyInjection>
```
加上 `Startup.cs` 与 `appsettings.json`。

## 6. 共享库 `Bing.Test.Shared` 提供什么

这是提高测试编写效率的核心，建议先翻一遍它再动手：

| 能力 | 类型 |
| --- | --- |
| 门控判定 | `IntegrationTestGate` |
| 门控特性 | `IntegrationFactAttribute` / `IntegrationTheoryAttribute` |
| 连接串解析 | `IntegrationTestConnectionStringResolver` |
| 安全护栏 | `IntegrationDatabaseSafetyValidator`（防止误伤非测试库） |
| 测试基类 | `IntegrationTestBase` |
| SQL 断言 | `SqlAssert` / `SqlExecutionAssert` / `SqlParameterAssert` |
| 通用断言辅助 | `AssertHelper` |
| 测试数据 | `FakeClock` / `FakeCurrentUser` |
| 契约与证据 | `ProviderContractRunner` / `ProviderRunMetadata` / `ProviderCapabilityEvidence` |

另有 `Bing.TestShare` / `Bing.TestShare.MySql`：提供 `TestConfig`、`Product`、`UnitOfWork` 等**共享领域模型**，写仓储/工作单元相关测试时直接复用。

## 7. 新增一个 Provider 时，测试要复制什么

以 `Bing.Dapper.Sqlite.Tests.Integration` 为模板，五件套：

1. **csproj**：import `framework.tests.props` + 4 个 `ProjectReference`（你的 Provider、`Bing.Dapper.Core`、`Bing.Data.Sql`、`Bing.Test.Shared`）
2. **`global-usings.cs`**
3. **`Infrastructure/` 三件套**：Collection（共享 Fixture）/ Fixture（建库、种子）/ Samples（表模型）
4. **`SqlQuery/` 测试类**：覆盖 CRUD、Lambda、事务、批量等路径
5. **`integration.local.runsettings`**：空白的 `EnvironmentVariables` 模板即可

需要 DI/Hosting 时再加 `Startup.cs` + `appsettings.json`，并在 csproj 配 `XunitStartupFullName` 与 `BingTestingUseXunitDependencyInjection`。

> **同时记得**：按 [最佳实践 §11.1](../guides/最佳实践.md) 与 `AGENTS.md` 的要求，涉及 Provider / 连接 / 执行器 / 查询工厂的改动**必须**跑 SQLite 本地集成测试（无需外部环境，所以没有借口跳过）。

## 8. 公开 API 门禁（RS00xx）

### 8.1 覆盖范围

`PublicAPI.Shipped.txt` + `PublicAPI.Unshipped.txt` **只有 7 个工程**存在：

| 工程 | Shipped / Unshipped 行数 |
| --- | --- |
| `Bing.Data.Sql` | 2258 / 721 |
| `Bing.Dapper.Core` | 128 / 25 |
| `Bing.Dapper.MySql` | — / 1 |
| `Bing.Dapper.Oracle` | — / 1 |
| `Bing.Dapper.PostgreSql` | — / 1 |
| `Bing.Dapper.SqlServer` | — / 1 |
| `Bing.Dapper.Sqlite` | — / 1 |

`common.props`（9–17 行）对这 7 个工程把 `RS0016;RS0017;RS0018;RS0026` 提为 **error**。

> ⚠ **其余工程的公开 API 变更不会被拦截**——改代码前先确认目标工程在这份名单里。

### 8.2 四条规则与处置

| 诊断 | 什么时候报 | 怎么处理 |
| --- | --- | --- |
| **RS0016** | 公开 API 未在基线中声明 | 往 `PublicAPI.Unshipped.txt` **追加一行** |
| **RS0017** | 公开 API 被删除或改名 | 在对应行前加 `*REMOVED*`（不要直接删行） |
| **RS0018** | 这个成员不应公开 | 收紧可见性（`internal` / `private`） |
| **RS0026** | 可选参数规范问题 | 拆成**显式重载** |

实录示例（`Bing.Data.Sql/PublicAPI.Unshipped.txt`）：

```
Bing.Data.Sql.SqlJoinOptions.RightAlias.get -> string
```

**发版时**：把 `Unshipped` 的内容并入 `Shipped`，然后清空 `Unshipped`。

> ⚠ RS0026 的「拆可选参数为显式重载」会影响**反射调用方与源生成器**——详见 [迁移指南](../migrations/README.md)。

## 10. CI 脚本与证据工具

`eng/ci/` 下三个脚本（**没有独立说明文档**，用法以脚本 `param()` 为准）：

| 脚本 | 主要参数 | 作用 |
| --- | --- | --- |
| `Invoke-ProviderIntegrationTests.ps1` | `-Provider MySql\|PostgreSql\|SqlServer`、`-Framework net6.0\|net8.0`、`-Configuration`、`-ResultsDirectory`（默认 `artifacts/provider-test-results`）、`-Settings`、`-ValidateOnly`、`-SelfTest` | 跑外部数据库集成测试并产出证据 |
| `Invoke-SqliteContractTests.ps1` | `-ResultsDirectory`（**必填**）、`-Framework`、`-Configuration`、`-RunName`（**必填**）、`-ReleaseEvidence` | 跑 SQLite 契约测试 |
| `Invoke-ReleaseCandidateValidation.ps1` | `-Configuration Release`、`-ResultsRoot artifacts/release-candidate`、`-SelfTest` | 编排：单元测试 + Provider + SQLite + FormalHost + 聚合 |

`eng/Bing.ProviderEvidence.Cli`（net8.0 控制台，无 README）三种模式：

```bash
# 聚合同一次发布验证的各类产物
--aggregate-output-directory <dir> [--rs0026-inventory <file>] [--api-gate-file <file>]

# 生成基线矩阵
--baseline-output-directory <dir>

# 默认：生成单个 Provider 的发布证据（参数很多）
--workspace-root --provider --framework --run-id --evidence-session-id --trx --summary \
  --matrix-json --matrix-markdown --binary-manifest --source-identity \
  --provider-version --database-version --driver-version --runtime-version \
  --operating-system --source-state
```

## 12. 提交前的测试自检清单

> `AGENTS.md` 对 `Bing.Data.Sql` 的改动有**硬性测试覆盖门槛**（完整版请直接读原文），这里摘要常用几条：

- [ ] 改动涉及 Provider / 连接 / 执行器 / 查询工厂 → **跑了 SQLite 本地集成测试**
- [ ] 改动默认值或默认实现 → 有**独立测试类**（不能只靠综合测试间接覆盖）
- [ ] 改动 SQL 输出 → 断言**完整 SQL 字符串**，不能只 `Contains` 片段
- [ ] 改动缓存键 → 覆盖了**命中**与**未命中**两种情形
- [ ] 改动 Provider 表名规则 → 有成功与失败两种场景
- [ ] 改动映射缓存 / 格式化热路径 / Builder 克隆 → 更新了 [基准测试基线](性能指南.md)（或说明不适用原因）
- [ ] 改动公开 API → 基线文件已更新（仅那 7 个工程有门禁）
- [ ] 提交时能给出「生产符号 → 测试方法」的映射
