## 2. 构建配置分层（props 是谁负责什么）

工程文件本身很薄，绝大多数配置靠 `.props` 层层 Import。改动前先看清该改哪一层：

| 文件 | 负责什么 |
| --- | --- |
| `common.props` | **全局公共**：`LangVersion=latest`、`NoWarn`（CS1591/NETSDK1138）、**统一输出路径**、`DocumentationFile`（生成 XML 文档），并按工程名给 7 个 SQL/Dapper 工程把 `RS0016/17/18/RS0026` 提升为 **error**；末尾 Import `asset/props/` 下四个 props 以及 `version.props` / `version.dev.props` |
| `framework.props` | 类库 **TFM = `netstandard2.0`**（`netstandard2.1` 那行已注释），再 Import `common.props` |
| `framework.tests.props` | 测试工程 TFM = **`net8.0;net6.0`** |
| `version.props` | **产品版本号**：`VersionMajor/Minor/Patch` + `VersionQuality`（当前 7.0.0 / `20250319-1`） |
| `version.dev.props` | ⚠ **名字有误导性**：它装的其实是**第三方依赖版本**，不是开发版号 |
| `asset/props/package.props` | NuGet 包元数据：作者、仓库地址、图标、License、Tags、ReleaseNotes，以及 `IncludeSymbols=true` + `SymbolPackageFormat=snupkg` |
| `asset/props/sourcelink.env.props` | Source Link（源码调试）配置 |
| `asset/props/target.feature.props` | 目标框架特性开关 |
| `asset/props/misc.props` | 杂项 |
| `asset/props/testing/*` | 测试相关（xunit V2/V3、VSTest runner、Shouldly / Moq / Coverlet） |

### 2.1 统一输出目录

`common.props` 把所有工程的输出重定向到仓库根：

```
Debug   → output/debug/
Release → output/release/
```

（根目录的 `output/` 已被 `.gitignore` 忽略。）所以别在各工程自己的 `bin/` 里找产物。

### 2.2 公开 API 门禁

`common.props` 里，**仅这 7 个工程**把分析器告警提升为编译错误：

```
Bing.Data.Sql、Bing.Dapper.Core、Bing.Dapper.MySql、Bing.Dapper.Oracle、
Bing.Dapper.PostgreSql、Bing.Dapper.SqlServer、Bing.Dapper.Sqlite
```

规则含义与处理：

| 规则 | 含义 | 怎么处理 |
| --- | --- | --- |
| `RS0016` | 公开 API **未在基线中声明** | 把新 API 加进 `PublicAPI.Unshipped.txt` |
| `RS0017` | 公开 API 被**删除/改名** | 在 `PublicAPI.Unshipped.txt` 对应行前加 `*REMOVED*` |
| `RS0018` | 公开 API 存在但**不应公开** | 收紧可见性 |
| `RS0026` | 新增公开成员**缺少可选参数相关的规范**（如滥用可选参数） | 拆成显式重载（7.0.0 已对大量 Fluent 扩展做过这个治理） |

基线文件成对存在：`PublicAPI.Shipped.txt`（已发布）+ `PublicAPI.Unshipped.txt`（未发布）。**发版时把 Unshipped 的内容并入 Shipped，并清空 Unshipped。**

另外 `Bing.Data.Sql.Analyzers` 有一份 `AnalyzerReleases.Unshipped.md`——那是**分析器诊断号**（如 `BINGSQL002`）的发布基线，与上面 7 个工程的 PublicAPI 基线是两套东西，别混。

> ⚠ 除这 7 个工程外，**其余工程的公开 API 变化不会被分析器拦截**。跨版本兼容性请自行把关，并在 [迁移指南](../migrations/README.md) 中记录。

## 3. 构建与测试（命令）

```bash
# 整体构建
dotnet build Bing.All.sln

# 单工程
dotnet build framework/src/Bing.Core/Bing.Core.csproj

# 单个测试工程（⚠ 路径是 framework/tests/，不是 tests/）
dotnet test framework/tests/Bing.Core.Tests/Bing.Core.Tests.csproj

# 全量测试（较慢）
dotnet test Bing.All.sln
```

测试工程约 30 个，位于 `framework/tests/`：`*.Tests`（单元）与 `*.Tests.Integration`（集成）成对出现，共享基建在 `Bing.Test.Shared` / `Bing.TestShare(.MySql)`。另有 `components/tests/Bing.Biz.Payments.Tests` 独立于主解决方案之外。

测试框架：xunit（V2/V3）+ VSTest runner + Shouldly / Moq / Coverlet。

### 3.1 集成测试门控

| 变量 | 作用 |
| --- | --- |
| `RUN_INTEGRATION_TESTS` | 全局开关，允许本地多 Provider 同跑；**受保护 CI 会显式清除它** |
| `RUN_MYSQL_INTEGRATION_TESTS` / `RUN_POSTGRESQL_INTEGRATION_TESTS` / `RUN_SQLSERVER_INTEGRATION_TESTS` / `RUN_ORACLE_INTEGRATION_TESTS` / `RUN_DORIS_INTEGRATION_TESTS` | Provider 级开关 |
| `ConnectionStrings__<Provider>Connection` | 各 Provider 连接串（配置键带双下划线） |
| `ALLOW_DATABASE_RESET_FOR_TESTS` | 允许测试重建数据库 |
| `BING_INTEGRATION_MYSQL_CROSS_DATABASE(_NAME)` | MySQL 跨库测试专用 |

- **SQLite** 集成测试默认可跑：直接 `dotnet test framework/tests/Bing.Dapper.Sqlite.Tests.Integration`（或 `Bing.EntityFrameworkCore.Tests`）。涉及数据库 Provider / 连接 / 执行器 / 查询工厂路径的改动**必须**跑。
- **外部数据库**测试一律**不得指向生产库**。
- `tests/runsettings/` 下有 `integration.{mysql,postgresql,sqlserver,oracle}.runsettings.example` 模板，复制成 `integration.runsettings.local`（已被 `.gitignore` 忽略）后填自己的连接串。
- 详见 [integration-testing.md](../testing/integration-testing.md) 与 [testing/database-integration-tests.md](../testing/database-integration-tests.md)。

# CI 冒烟（快）
dotnet run --project framework/tests/Bing.Data.Sql.Benchmarks/Bing.Data.Sql.Benchmarks.csproj -c Release -- --ci-smoke --filter "*SqlCiSmokeBenchmarks*" --artifacts "BenchmarkDotNet.Artifacts/ci"

| 参数 | 说明 |
| --- | --- |
| `--ci-smoke` / `--e2e-smoke` | 两种冒烟模式 |
| `--filter` | BenchmarkDotNet 的过滤器 |
| `--artifacts <dir>` | 指定产物目录 |

**两个产物目录别搞混**：

| 目录 | 性质 |
| --- | --- |
| `BenchmarkDotNet.Artifacts/` | BenchmarkDotNet 默认输出，**已被 `.gitignore` 忽略** |
| `artifacts/benchmarks/` | 正式归档证据目录，供 ProviderEvidence CLI 校验 |

改到映射缓存、格式化热路径或 Builder 克隆逻辑时，需要更新基准或说明不适用原因（见 [CONTRIBUTING §5](../../CONTRIBUTING.md)）。

## 5. CI

### 5.1 AppVeyor（`appveyor.yml`）

- 镜像 `Visual Studio 2022`，只在 **`master`** 分支跑，`configuration: Release`；
- 5 个 lane，由环境变量 `PROVIDER_TEST_LANE` 选择：

| lane | 做什么 |

- ⚠ **`deploy` 段已注释**，AppVeyor **不会**自动发布 NuGet 包（`nuget.disable_publish_on_pr: true`）。

## 7. 发版与 NuGet 打包

**当前是手工流程**，没有自动化发布：

```bash
# framework/Publish.bat 或 components/Publish.bat
cd framework
Publish.bat
```

脚本做的事：

1. 清理并重建 `nuget_pub/` 目录；
2. 逐个工程 `dotnet pack -c Release -o nuget_pub`（`framework/Publish.bat` 里列了约 50 个包，`components/Publish.bat` 列 `components/src` 下的包）；
3. 删掉 `*.symbols.nupkg`；
4. **交互式** `set /p key=input key:` 让你输入 NuGet API Key；
5. 逐个 `dotnet nuget push <pkg> -k <key> -s https://api.nuget.org/v3/index.json`。

## 7.1 包级 README（`README.md` 内嵌进 nupkg）

`framework/src/<工程>/README.md` 与 `components/src/<工程>/README.md` 会被**自动打进 NuGet 包**，并在 nuget.org 包页面直接展示（客户看到的第一屏就是它）。

实现方式是 `asset/props/package.props` 里的条件配置：

```xml
<PropertyGroup Condition="Exists('$(MSBuildProjectDirectory)/README.md')">
  <PackageReadmeFile>README.md</PackageReadmeFile>
</PropertyGroup>
<ItemGroup Condition="Exists('$(MSBuildProjectDirectory)/README.md')">
  <None Include="$(MSBuildProjectDirectory)/README.md" Pack="true" PackagePath="\" />
</ItemGroup>
```

要点：

- **条件化**——工程没有 `README.md` 时不会声明 `PackageReadmeFile`，避免 `NU5039`；
- **新增工程必须同时创建 `README.md`**（否则包页面没有说明）；
- 包图标 `icon.png` 的打包声明在 `asset/props/misc.props`，`PackageIcon` 属性在 `package.props`——**两处必须配套存在**，否则 pack 报 `NU5046`。已用 `framework/src/Bing.Core` 实测通过：包内同时含 `README.md`、`icon.png`、`LICENSE` 与 XML 文档。

包级 README 的推荐结构（模板见 `framework/src/Bing.Core/README.md`）：

| 小节 | 内容 |
| --- | --- |
| **徽章行**（H1 之后第一行） | NuGet 版本 + 下载量 + TFM 三个徽章，见下方说明 |
| 引言块 | 一句话定位 + 目标框架 / 分层 / 版本 / 源文件数 / 上游 Bing 包 / 三方依赖 |
| 这是什么 | 2–4 句说明职责 |
| 安装 | `dotnet add package Bing.Xxx` |
| 快速上手 | 最小可运行代码 |
| 注册入口 | 入口方法 / 命名空间 / 说明（无入口的包明确写"需手动装配"） |
| 关键类型 | 类型 / 命名空间 / 说明 |
| 与其它包的关系 | 上游依赖、下游引用者、三方包 |
| 注意事项 | 易踩的坑（如返回 `void` 不能链式、入口不在 `IServiceCollection`） |
| 更多文档 | **用绝对 GitHub URL**（nuget.org 上相对链接会失效）+ NuGet 包页面 |
| 许可证 | MIT |

> ⚠ 文档链接**必须写绝对路径**（`https://github.com/bing-framework/Bing.NetCore/blob/master/docs/...`）。包页面上的相对链接指向 nuget.org 自身，会 404。

**徽章行**：67 份包级 README 的 H1 之后都已插入三个徽章（NuGet 版本 / 下载量 / TFM），模板：

```markdown
# Bing.Core
[![NuGet](https://img.shields.io/nuget/v/Bing.Core.svg)](https://www.nuget.org/packages/Bing.Core/) [![NuGet Downloads](https://img.shields.io/nuget/dt/Bing.Core.svg)](https://www.nuget.org/packages/Bing.Core/) ![TFM](https://img.shields.io/badge/TFM-netstandard2.0-blue.svg)
```

- 徽章依赖外部服务 `img.shields.io`。若某天 nuget.org 收紧图片策略导致徽章不显示，删掉这一行即可，不影响包内容。
- **TFM 徽章是静态文本**，多目标框架升级后（如 `netstandard2.0` → `net6.0`）要手动改这一行；版本与下载量徽章会自动跟随 nuget.org。
- 新增工程复制模板时，把三处包名与 TFM 一起改掉。

### 7.2 发版清单

- [ ] 更新 `version.props` 的 `VersionMajor/Minor/Patch/VersionQuality`（**不要在 `.csproj` 里写版本**）；

## 8. 代码模板（`templates/`）

| 目录 | 说明 |
| --- | --- |
| `templates/CodeSmith/` | **CodeSmith 代码生成器**：独立 `.sln` / `.csproj`，内置 `CodeSmith.Engine` / `SchemaExplorer` 的 dll，约 50 个 `.cst` 模板，按 Domains / Datas / Services / Presentation / Tests / PersistObjects 分组 |

⚠ 说明：仓库内**没有任何文档**描述它的用法；模板内容年代较早（生成的代码风格可能已与当前框架 API 不一致，例如 SQL 查询 API 在 7.0.0 已大幅收敛）。**使用前请先检查生成结果能否编译**。
