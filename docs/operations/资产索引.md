## 本文定位

仓库里除了 `docs/` 下的产品文档，还有几类**历史记录 / 过程产物 / 工具资产**：`ai_docs/`、`artifacts/`、`templates/`、`docs/plans/`、`docs/ai-workflow/`。它们**不是**框架的使用或设计文档，但体量很大（`ai_docs/` 约 79 个 md，`artifacts/` 下还有大量报告），不说明清楚很容易误读。

本文回答三件事：**它们是什么、是否入库、还能不能信**。

## 2. `ai_docs/` —— AI 任务档案

### 2.1 组成

| 分类 | 内容 |
| --- | --- |
| 治理/设计稿（3 篇） | `sql-lambda-query-design.md`（Lambda 查询设计）、`sql-provider-development.md`（Provider 开发）、`sql-public-api-governance.md`（公开 API 治理） |
| 分阶段记录（9 篇） | `stage-00-baseline.md` → `stage-08-multidatabase-completion.md` |
| 任务档案（`tasks/`） | 每个任务目录含 `plan.md` / `execution.md` / `progress.md` / `review.md` / `test-report.md` / `benchmark-report.md` 等，任务 ID 形如 `BING-SQL-RC-HARDENING-20260828-004` |

### 2.2 怎么读

1. **先读 3 篇治理/设计稿**——它们解释了 `Bing.Data.Sql` 的几个关键约束（`sql-public-api-governance.md` 尤其值得读，它解释了 PublicAPI 基线与分析器门禁的来由，而 `docs/` 下只有一行事实说明）。
2. `stage-00` ~ `stage-08` 是一次**渐进式重构的阶段记录**，按顺序读能还原演进脉络。
3. `tasks/` 下的目录**按需查阅**——只在你需要追查"某个 API 为什么变成现在这样"时才有价值。

### 2.3 ⚠ 时效性声明（重要）

- 这些档案记录的是 **2026-08 ~ 2026-09 期间**的一轮 `Bing.Data.Sql` 加固工作，属于**历史快照**。
- 其中的 API 名称、测试数量、基准数字**不代表当前代码状态**。例如 7.0.0 之后 SQL 查询 API 又经过收敛，`ai_docs` 里旧的任务报告仍可能写着已被删除的入口。
- **以源码为准**。若 `ai_docs/` 与源码 / `docs/` 下正式文档冲突，**信任源码与 `docs/`**，并考虑在 `ai_docs/` 对应文件顶部加一行过期提示。

## 3. `artifacts/` —— 过程产物（不入库）

`artifacts/` 已被 `.gitignore` 忽略，**提交时不会带入**。由 `eng/ci/*.ps1` 与基准工程生成，由 `eng/Bing.ProviderEvidence.Cli` 校验。

| 子目录 | 内容 | 怎么读 |
| --- | --- | --- |
| `test-results/` | 单元/集成测试的 TRX、JSON、能力矩阵（`provider-capability-matrix.md` 汇总各 Provider 支持情况） | 看 `provider-capability-matrix.md` 最快 |
| `provider-test-results/<provider>-<tfm>-<时间戳>-<guid>/` | 按 Provider + TFM + 时间戳归档的集成测试结果与 `run-metadata` | 用时间戳判断新旧 |
| `benchmarks/` | 基准测试归档证据（含 BenchmarkDotNet 的 github 报告 md） | 与 `BenchmarkDotNet.Artifacts/`（默认输出、已忽略）区分 |
| `plans/`、`reports/` | 历史任务计划与最终报告 | — |
| `release-candidate/` | release lane 的验证产物 | — |

**解读要点**：这些是**单次任务的证据**，不是全局基线。报告里的测试数量**不构成当前 commit 的验收证据**——要验收请以当前 `dotnet test` 结果与 TRX 为准。

## 4. `templates/` —— 代码生成器（历史遗留）

| 目录 | 说明 |
| --- | --- |
| `templates/CodeSmith/` | 独立 `.sln` + `.csproj`，内置 `CodeSmith.Engine` / `SchemaExplorer` dll，约 50 个 `.cst` 模板（Domains / Datas / Services / Presentation / Tests / PersistObjects） |
| `templates/Pd/` | PowerDesigner 数据模型（`.xdb` / `.pdm`） |

- **与框架运行时无依赖关系**，不在 `Bing.All.sln` 内；
- 用途：从数据库模型**批量生成分层代码**；
- ⚠ **年代较早**：生成的代码风格可能已与现行 API 不符（7.0.0 后 SQL 查询 API 大幅收敛）。**使用前务必先验证生成结果能编译**；
- ⚠ 仓库内**没有**它的使用文档。

## 6. 维护约定

- **不要**把 `artifacts/` 或 `BenchmarkDotNet.Artifacts/` 提交进仓库（已在 `.gitignore` 中）；若需要长期留档，把关键结论**抄进** `docs/` 下的正式文档或 [ReleaseNotes](../ReleaseNotes.md)。
- 在 `ai_docs/tasks/` 下新建任务目录时，沿用既有命名（`plan.md` / `execution.md` / `review.md` ...）与 `<任务ID>` 目录名规范。
- 若某份 `ai_docs/` 文档已被后续变更推翻，**在其顶部加一行过期提示**并指向当前权威文档，不要直接删（保留决策脉络）。
- 新增任何一类资产目录时，回到本文 §1 的表格补一行。
