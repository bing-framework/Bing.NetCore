# 日志使用说明

> **适用版本**：框架 `7.0.0`（`version.props`）｜ 目标框架：类库 `netstandard2.0`、Web / 应用 `net6.0`｜ 内容核对：2026-09-18｜ 版本历史见 [发行说明](../ReleaseNotes.md)

> **一句话定位**：本文是 `Bing.Logging` 的**使用手册**——从装包、注册，到用链式 API 写出第一条**带结构化字段**的日志。
>
> **与《日志与可观测性》的分工**：本文只讲「**怎么用 `ILog` 写日志**」；那篇讲「**整条可观测链路怎么搭**」（Enricher、请求留痕、TraceId 贯通、SkyAPM、Dashboard）。写日志看这篇，搭链路看那篇。
>
> **一句话认清这套日志**：它是 `Microsoft.Extensions.Logging` 之上的一层**链式包装**，不是替代品。底层仍然是 `ILogger` / `ILoggerFactory`，Serilog 也只是作为一个 Provider 挂上去。所以 `ILogger<T>` 和 `ILog<T>` **可以同时用，互不冲突**（集成测试里就是两者并存）。
>
> **所有类型与行号均取自源码。** 若源码变了而本文没变，请信任源码并回来修正本文。

## 1. 五分钟上手

### 1.1 装哪些包

| 包 | 必需？ | 提供什么 |
| --- | --- | --- |
| `Bing.Logging` | ✅ 必需 | `ILog` / `ILog<T>` 链式 API、`ILogFactory`、`LogContext`，以及唯一的注册入口 `AddBingLogging` |
| `Bing.Logging.Serilog` | 可选 | Serilog 配置辅助：级别映射 `ConfigLogLevel`、一批 `Enrich.WithXxx()` 扩展 |
| `Bing.Logging.Sinks.Exceptionless` | 可选 | Exceptionless Sink（⚠ 入口在 `Serilog` 命名空间，见 §8） |
| `Bing.AspNetCore.Serilog` | Web 可选 | 4 个 ASP.NET Core 专用 Enricher 字段 + `UseBingSerilogEnrichers` |

只想要链式 API、日志走控制台或已有的 `ILoggerProvider`，装 `Bing.Logging` 一个就够。

### 1.2 两步注册

```csharp
using Bing.Logging;

// 第一步：注册 Bing 日志管道
services.AddBingLogging(options =>
{
    options.ClearProviders = false;   // 默认 false：不清空已有 ILoggerProvider
});

// 第二步：照常配置底层 Provider（Bing 不管这一步）
services.AddLogging(builder =>
{
    builder.AddConsole();
    // 或 builder.AddSerilog();
});
```

⚠ **`AddBingLogging` 返回的不是 `IServiceCollection`**，而是 **`BingLoggingBuilder`**（`ServiceCollectionExtensions.cs:17`）：

```csharp
public static BingLoggingBuilder AddBingLogging(
    this IServiceCollection services,
    Action<BingLoggingOptions> setupAction = null);
```

所以**不能**在它后面继续链式调用别的服务注册：

```csharp
// ❌ 编译不过 —— BingLoggingBuilder 上没有 AddXxx
services.AddBingLogging().AddMemoryCache();

// ✅ 分开写，或用 .Services 属性
services.AddBingLogging();
services.AddMemoryCache();

services.AddBingLogging().Services.AddMemoryCache();   // 也可以
```

`BingLoggingBuilder` 只有 `Services` 一个成员（`BingLoggingBuilder.cs:22`）。

`BingLoggingOptions` 的可配置项（`BingLoggingOptions.cs:26,33`）：

| 成员 | 默认值 | 说明 |
| --- | --- | --- |
| `ClearProviders` | `false` | 置 `true` 会清空此前注册的 `ILoggerProvider` |
| `RegisterExtension(IBingLoggingOptionsExtension)` | — | 追加自定义扩展 |
| `Extensions` | `internal` | 外部拿不到 |

### 1.3 三种拿到日志器的方式

```csharp
// ① 注入泛型日志器（推荐）——类别名自动取 TCategoryName 的全名
public class OrderService
{
    private readonly ILog<OrderService> _log;
    public OrderService(ILog<OrderService> log) => _log = log;
}
```

```csharp
// ② 注入工厂，按类型或字符串自行创建（动态类别名场景）
public class ReportJob
{
    private readonly ILog _log;
    public ReportJob(ILogFactory factory) => _log = factory.CreateLog(typeof(ReportJob));
}

// ILogFactory 只有两个方法（ILogFactory.cs:13,20）
ILog CreateLog(string categoryName);
ILog CreateLog(Type type);
```

```csharp
// ③ 注入非泛型 ILog
private readonly ILog _log;
```

⚠ **第 ③ 种的类别名是字面量 `"default"`**，不是调用方的类名——注册代码写得很直白（`ServiceCollectionExtensions.cs:22`）：

```csharp
services.TryAddTransient(typeof(ILog),
    t => t.GetService<ILogFactory>()?.CreateLog("default") ?? NullLog.Instance);
```

后果：所有注入 `ILog` 的地方，日志类别**全是 `default`**，按命名空间做 `MinimumLevel.Override` 或日志筛选时**区分不出来**。想按类过滤就用 `ILog<T>`。

### 1.4 第一条日志

```csharp
// 最简：一条消息 + 一个级别终结方法
_log.Message("订单创建成功，订单号 {OrderNo}", orderNo).LogInformation();

// 带异常
_log.Exception(ex)
    .Message("订单 {OrderNo} 支付失败", orderNo)
    .LogError();

// 带结构化字段
_log.Message("订单 {OrderNo} 已支付", orderNo)
    .ExtraProperty("Amount", 199.9m)
    .Tag("payment")
    .LogInformation();
```

**链式 API 的规矩**：先攒状态（`Message` / `Exception` / `Property` / `State` / `Tag` …），**最后调一个 `LogXxx()` 才会真正写出去**。中间那些方法只是往实例里塞数据，不写日志。

### 1.5 最小装配模板

取自集成测试 `framework/tests/Bing.Logging.Serilog.Tests.Integration/Startup.cs:44-62`——这是仓库里**最完整的一份可运行装配**：

```csharp
public void ConfigureServices(IServiceCollection services)
{
    // 1) Bing 日志管道
    services.AddBingLogging(x => { });

    // 2) 上下文访问器（非 Web 宿主需要显式注册；Web 宿主由约定式 DI 自动替换为 AspNetCoreLogContextAccessor）
    services.AddSingleton<ILogContextAccessor, LogContextAccessor>();

    // 3) 底层 Provider：Serilog
    services.AddLogging(loggingBuilder =>
    {
        var configuration = services.GetConfiguration();
        Serilog.Log.Logger = new LoggerConfiguration()
            .Enrich.FromLogContext()
            .Enrich.WithLogContext()          // Bing 的 LogContext Enricher，见 §6
            .Enrich.WithLogLevel()
            .ReadFrom.Configuration(configuration)
            .ConfigLogLevel(configuration)    // Bing 的级别映射，见 §4
            .CreateLogger();
        loggingBuilder.AddSerilog();
    });

    services.AddBing();
}
```

### 2.3 写完自动清空

每次 `LogXxx()` 结束都会 `Clear()`（`Log.cs:355-358` 的 `finally`），把级别、事件 ID、异常、状态、属性、消息全部复位。所以同一个 `ILog<T>` 实例**可以安全地连续写多条**，不会串味：

```csharp
_log.Message("第一条").LogInformation();
_log.Message("第二条").LogWarning();   // 不会带着"第一条"
```

## 3. 消息模板与参数化

占位符语法沿用 `Microsoft.Extensions.Logging`（也就是 Serilog 的）约定，实测支持的几种写法（均取自 `LogTest.cs`）：

```csharp
// 具名占位符
_log.Message("订单 {id}_{code}", id, code).LogTrace();          // LogTest.cs:58

// 多个 Message 拼接，占位符按顺序对应
_log.Message("前缀 {id}_{code}_", id, code)
    .Message("{name}_{note}", name, note)
    .LogTrace();                                                 // LogTest.cs:67-69

// {@X}：解构对象（展开成结构化字段）
_log.Message("订单 {@Product}", product).LogTrace();              // LogTest.cs:78

// {$X}：强制字符串化（不展开）
_log.Message("订单 {$Product}", product).LogTrace();              // LogTest.cs:88

// 字典同样支持 @ / $
_log.Message("数据 {@Dictionary}", dict).LogTrace();              // LogTest.cs:98
```

⚠ **源码里有一处未解决的 TODO**（`Log.cs:320`）：

```csharp
result.AddRange(LogProperties.Values);//TODO: 此处造成字符串拼接异常
```

即：当**同时**使用了 `Property(...)`（产生 `LogProperties`）和 `Message(..., args)`（产生 `LogMessageArgs`）时，参数数组是「属性值在前、消息参数在后」拼起来的。如果两部分的编号对不上模板里的占位符顺序，会出现消息渲染异常。**规避方式**：不要在同一条日志里混用 `Property` 与带参 `Message`；要结构化字段请用 `ExtraProperty`。

## 4. 级别与配置

### 4.1 配置节

读的是标准节 **`"Logging:LogLevel"`**（`LoggerConfigurationExtensions.cs:23`）：

```json
{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft": "Warning",
      "Bing": "Debug"
    }
  }
}
```

处理规则（`LoggerConfigurationExtensions.cs:24-32`）：

- 键为 `Default` → `MinimumLevel.ControlledBy(new LoggingLevelSwitch(...))`（**全局动态级别**，运行期可改）
- 其它键 → `MinimumLevel.Override(key, level)`

### 4.2 级别名映射（`LogLevelSwitcher.cs:32-45`）

| 配置里写的 | Serilog `LogEventLevel` |
| --- | --- |
| `Trace` | `Verbose` |
| `Debug` | `Debug` |
| `Information` | `Information` |
| `Warning` | `Warning` |
| `Error` | `Error` |
| `Critical` | `Fatal` |
| **`None`** | **`Fatal`** ⚠ |
| **其它任何值** | **`Warning`** ⚠ |

两个坑：

1. **`"None"` 不是"关闭日志"，而是映射到 `Fatal`**——本想关掉，结果只剩最严重的日志。
2. **未知级别值静默降级为 `Warning`**。写 `"Info"`（不是合法名）不会报错，只表现为「我把级别调低了却看不到 Debug 日志」。

匹配是 `ToUpperInvariant()` 后比较，所以大小写不敏感。

### 4.3 用 `IsEnabled` 短路

拼装大对象（尤其 `{@X}` 解构）前先判断，能省掉序列化开销：

```csharp
if (_log.IsEnabled(LogLevel.Debug))
    _log.Message("调试快照 {@Snapshot}", BuildSnapshot()).LogDebug();
```

## 5. Serilog 装配

`Bing.Logging.Serilog` **只有配置文件级的辅助方法，没有任何"一键接入"**：

| 类型 | 方法 | 行号 |
| --- | --- | --- |
| `LoggerConfigurationExtensions` | `ConfigLogLevel(this LoggerConfiguration, IConfiguration)` —— **该类唯一方法** | :17 |
| `LoggerEnrichmentConfigurationExtensions` | `WithLogContext()` | :16 |
| | `WithLogLevel()` | :28 |
| | `WithProperty(KeyValuePair<string,object>)` | :41 |
| | `WithFunction(...)` ×3 重载 | :57, :75, :94 |
| | `WithEnvironment(string)` | :113 |

完整管道（顺序有讲究）：

```csharp
Serilog.Log.Logger = new LoggerConfiguration()
    .ReadFrom.Configuration(configuration)   // 先读 Serilog 自己的配置（Sinks 等）
    .ConfigLogLevel(configuration)            // 再覆盖 Bing 的级别映射
    .Enrich.FromLogContext()                  // Serilog 原生
    .Enrich.WithLogContext()                  // Bing：把 LogContext 字段写进日志事件
    .Enrich.WithLogLevel()
    .WriteTo.Console()
    .CreateLogger();

services.AddLogging(b => b.AddSerilog());
```

`.Enrich.WithLogContext()` **是可选的**——不加就只是少了 `TraceId` / `UserId` / `TenantId` 等结构化字段，不会报错。加了才有 §6 那批字段。

## 6. `LogContext` 与 TraceId

### 6.1 上下文字段（`LogContext.cs`）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `TraceId` | `string` | 链路标识 |
| `UserId` / `TenantId` / `SessionId` | `string` | 用户 / 租户 / 会话 |
| `Application` / `Environment` | `string` | 应用名 / 环境名 |
| `Ip` / `Host` / `Browser` / `Url` | `string` | 客户端与请求信息 |
| `IsWebEnv` | `bool` | 是否 Web 环境 |
| `Tags` | `List<string>` | 标签 |
| `Data` | `IDictionary<string, object>` | 任意扩展数据 |

当前上下文通过 `AsyncLocal` 存取（`LogContext.cs:82-91`），`LogContext.Current` 可直接读写。

### 6.2 谁在填充

| 环境 | 实现类 | 填充内容 |
| --- | --- | --- |
| 非 Web | `LogContextAccessor`（`LogContextAccessor.cs:32`） | 仅 `TraceId`（新 GUID）+ `Host` |
| Web | `AspNetCoreLogContextAccessor`（`[Dependency(Scoped, ReplaceExisting = true)]`） | `Ip` / `Browser` / `Url` / `UserId` / `TenantId` / `Application` + `Data` 里的用户名、租户名等 |

Web 版带 `[Dependency(ServiceLifetime.Scoped, ReplaceExisting = true)]`，所以只要用了约定式 DI，**它会顶掉默认注册**，不需要手工换。

`TraceId` 的取值优先级（`AspNetCoreLogContextAccessor.cs:76-85`）：

1. `TraceIdContext.Current.TraceId`（框架链路标识）
2. 请求头 `X-Correlation-Id`
3. `HttpContext.TraceIdentifier`
4. 都不行 → 新 GUID

### 6.3 ⚠ TraceId 不会自动进 `ILog` 的属性

`Log.AddLogContext()` 里的 TraceId 注入**整段被注释掉了**（`Log.cs:256-265`）：

```csharp
protected virtual void AddLogContext()
{
    if (LogContext == null)
        return;
    //if (!string.IsNullOrWhiteSpace(LogContext.TraceId))
    //{
    //    Debug.WriteLine($"【{nameof(Log)}】TraceId: {LogContext.TraceId}");
    //    Property("TraceId", LogContext.TraceId);
    //}
}
```

所以：**用 `ILog` 写的日志，消息模板里不会自动带 `TraceId`**。

它只会出现在**装了 `.Enrich.WithLogContext()` 的 Serilog 事件**上——由 `LogContextEnricher` 补（`Enrichers/LogContextEnricher.cs:61-71`）。想要 TraceId 就必须走 Serilog + 那个 Enricher；直接用 `AddConsole()` 的话，日志里没有 TraceId。

### 6.4 两处源码缺陷（已在 [功能完成度](../architecture/功能完成度.md) 登记）

| 位置 | 问题 |
| --- | --- |
| `AspNetCoreLogContextAccessor.cs:57` | `context.Browser = WebClientInfoProvider.ClientIpAddress;` —— **浏览器字段写的是客户端 IP** |
| `Enrichers/LogContextEnricher.cs:106-108` | `AddTenantId` 判断用的是 `_context.TenantId`，**写入的却是 `_context.UserId`** |

两者都不报错，只表现为「日志里的 Browser 是 IP」「TenantId 和 UserId 值一样」。

## 7. 作用域与结构化字段

### 7.1 `BeginScope`

```csharp
using (_log.BeginScope(new { OrderNo = orderNo, UserId = userId }))
{
    // 这段里的日志都会带上 scope 字段
    _log.Message("开始扣款").LogInformation();
}
```

`BeginScope` 直接转调底层 `ILoggerWrapper.BeginScope`（`Log.cs:196`），语义与 `ILogger.BeginScope` 一致。

### 7.2 `Set` / `ExtraProperty` / `Tags`

`Set` 是底层入口，扩展方法都是它的语法糖：

```csharp
// 等价写法
_log.ExtraProperty("Amount", 199.9m);
_log.Set(x => x.Context.SetExtraProperty("Amount", 199.9m));

_log.Tag("payment");
_log.Set(x => x.Context.SetTags("payment"));
```

`WriteLog` 会把 descriptor 里的 scope 状态取出来包一层 `BeginScope`（`Log.cs:336-337`），所以 `ExtraProperty` / `Tags` 设的字段**只作用于这一条日志**，不会污染后续。

## 9. 生命周期与并发

| 服务 | 生命周期 | 注册位置 |
| --- | --- | --- |
| `ILogFactory` → `LogFactory` | **Singleton** | `ServiceCollectionExtensions.cs:19` |
| `ILogContextAccessor` → `LogContextAccessor` | **Scoped** | `:20` |
| `ILog<>` → `Log<>` | **Transient** | `:21` |
| `ILog` → `CreateLog("default")` | **Transient** | `:22` |

全部用 `TryAdd*`，**重复调用 `AddBingLogging` 是安全的**，不会重复注册。

⚠ **不要在 Singleton 里注入 `ILogContextAccessor` / `ILog<T>`**。Accessor 是 Scoped，上下文靠 `AsyncLocal` 传递，Singleton 里持有会导致上下文串号或拿不到 Web 请求信息。

⚠ **写日志失败不会抛给调用方**。`WriteLog` 整个包在 `try/catch` 里，异常被降级为一条 `LogCritical`（`Log.cs:350-354`）：

```csharp
catch (Exception e)
{
    Logger.LogCritical(LogErrorEventId, e, $"未知异常错误信息: {e.Message}.");
    return this;
}
```

好处是日志系统故障不会拖垮业务；代价是**Sink 挂了你只能从那条 Critical 里看出来**。

| 5 | `LogLevelSwitcher.cs:42` | `"None"` → `Fatal` | 想关日志反而只留最严重级别 |
| 6 | `LogLevelSwitcher.cs:43` | 未知级别 → `Warning` | 写错级别名静默生效为 Warning |
| 7 | `ServiceCollectionExtensions.cs:22` | 非泛型 `ILog` 类别名固定 `"default"` | 按命名空间过滤/分级失效 |

第 1–4 条已在 [功能完成度](../architecture/功能完成度.md) 登记（只做记录，未改代码）。

## 11. 防误用清单

| ❌ 不要这样 | ✅ 应该这样 | 原因 |
| --- | --- | --- |
| `services.AddBingLogging().AddXxx()` | 分开写，或用 `.Services` | 返回 `BingLoggingBuilder`，不是 `IServiceCollection` |
| 注入 `ILog` 期望类别名是自己的类 | 用 `ILog<T>` | 非泛型 `ILog` 类别名固定 `"default"` |
| `Property("Age", 18)` | `Property("Age", "18")` 或 `ExtraProperty("Age", 18)` | `Property` 的值**只能是 string** |
| 同一条混用 `Property` + `Message(..., args)` | 结构化字段改用 `ExtraProperty` | 参数数组拼接有 TODO 缺陷（§3） |
| 只 `AddBingLogging` 就指望有 TraceId | 加 Serilog + `.Enrich.WithLogContext()` | TraceId 只由 Enricher 补（§6.3） |
| `"LogLevel": { "X": "None" }` 想关掉 | 用真的最高级别或移除该 Sink | `None` 映射到 `Fatal`（§4.2） |
| `"LogLevel": { "X": "Info" }` | `"Information"` | 非法名静默变 `Warning` |
| Singleton 里注入 `ILogContextAccessor` | Scoped 或用 `ILogFactory` 现场造 | 上下文靠 `AsyncLocal` + Scoped 传递 |
| 以为日志写失败会抛异常 | 监控 `Log.LogErrorEventId`(91000) 的 Critical | `WriteLog` 吞异常（§9） |
