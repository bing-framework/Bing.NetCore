# 包索引（按场景反查该装哪些包）

> **适用版本**：框架 `7.0.0`（`version.props`）｜ 目标框架：类库 `netstandard2.0`、Web / 应用 `net6.0`｜ 内容核对：2026-09-18｜ 版本历史见 [发行说明](../ReleaseNotes.md)

> **一句话定位**：回答「**我要做 X，该装哪些 NuGet 包？**」。每个包的完整用法看它自己的 README（路径见文末），本文只解决「找包」这一步。
>
> **NuGet 包名 = 工程目录名**（已核对：67 个包中显式声明 `PackageId` 的 65 个，**无一例外与目录名一致**），所以看到目录名就等于包名。
>
> **版本**：统一由 `version.props` 管理，**不要在 csproj 里写版本号**。

## 1. 三十秒反查表

| 我要做…… | 装这些包 | ⚠ 必读提醒 |
| --- | --- | --- |
| **最小 Web API 跑起来**（模块 + 统一响应） | `Bing.AspNetCore`、`Bing.AspNetCore.Mvc` | 非 Web 宿主还要手动 `provider.UseBing()` |
| **业务 CRUD + 迁移（EF Core）** | `Bing.Ddd.Domain`、`Bing.Ddd.Application.Contracts`、`Bing.Ddd.Application`、`Bing.EntityFrameworkCore` + 对应 Provider、`Bing.AspNetCore.Mvc` | 唯一有迁移的一支 |
| **只连 MySQL，工程是老 netstandard2.0** | `Bing.FreeSQL.MySql`（会带上 `Bing.FreeSQL`） | 无迁移；异步查询会退化为同步阻塞 |
| **复杂报表 / 批量写入 / 跨库 Join / 存储过程** | `Bing.Data.Sql` + `Bing.Dapper.<库>` | **没有** `IUnitOfWork` / `IStore` / 审计，它不是 ORM |
| **JWT 认证登录** | `Bing.AspNetCore.Authentication.JwtBearer`、`Bing.Security` | 密钥必须配 `JwtOptions:Secret`（为空会抛异常）；详见 [安全指南 §2](../operations/安全指南.md) |
| **用户 / 角色 / RBAC** | `Bing.Permissions`、`Bing.Security` | 框架**没有**全局权限过滤器，要自己加（参考 admin 的 `AuthorizeControllerModelConvention`） |
| **多租户** | `Bing.MultiTenancy`、`Bing.AspNetCore.MultiTenancy` | 🔴 解析租户 ≠ 过滤数据，**三支 ORM 都没有内置租户过滤**，漏配就是跨租户泄露 |
| **进程内事件** | **不用装**，`Bing.Core` 自带 `ISimpleEventBus` | 别误用消息总线 |
| **跨服务事件（CAP + Outbox）** | `Bing.Events` | 订阅用 `[EventHandler]`，**不是** `[CapSubscribe]` |
| **Redis 缓存** | `Bing.Caching` + `Bing.Caching.CSRedis`（或 `Bing.Caching.FreeRedis`） | ⚠ **没有 `AddCache`**，必须 `RedisHelper.Initialization(...)` 后手工 `AddScoped<ICache, CSRedisCacheManager>()` |
| **分布式锁** | `Bing.Locks.CSRedis` | 入口 `AddRedisDistributedLock` |
| **发邮件** | `Bing.Emailing` + `Bing.MailKit` | ⚠ `AddMailKit` 在**两个命名空间**（`Bing.MailKit.Extensions` 真 MailKit / `Bing.Emailing.Smtp` 走 `System.Net.Mail`） |
| **对象映射** | `Bing.ObjectMapping` + `Bing.AutoMapper` | 入口 `AddAutoMapper` |
| **文本模板** | `Bing.TextTemplating` + `Bing.TextTemplating.Scriban` | ⚠ **没有任何 `IServiceCollection` 扩展**，必须手动装配 `BingTextTemplatingOptions` |
| **本地化** | `Bing.Localization`（可选 `.Abstractions`） | — |
| **AOP / `[UnitOfWork]` 自动提交** | `Bing.Aop.AspectCore`、`Bing.Uow` | 🔴 入口是 **`EnableAop`**（没有 `AddAop`）；不启用则 `[UnitOfWork]` 静默失效、数据不落库 |
| **Serilog 日志** | `Bing.Logging`、`Bing.Logging.Serilog`（Web 再加 `Bing.AspNetCore.Serilog`） | — |
| **日志发到 Exceptionless** | `Bing.Logging.Sinks.Exceptionless` | ⚠ 入口是 **`WriteTo.Exceptionless`**，在 `Serilog` 命名空间，不在 `IServiceCollection` 上 |
| **SQL 链路追踪（SkyAPM）** | `Bing.Extensions.SkyApm.Diagnostics.Sql` | 入口 `AddSqlQuery(this SkyApmExtensions)`，同样不在 `IServiceCollection` 上 |
| **支付（支付宝 / 微信）** | `Bing.Biz.Payments` | `AddPay` 系列，⚠ **返回 `void` 不能链式** |
| **第三方登录（QQ / 微信 / 微博…）** | `Bing.Biz.OAuthLogin` | 100+ 源文件 / 10+ 提供方 |
| **参数校验** | `Bing.Validation`（可选 `.Abstractions`） | — |
| **审计字段自动填充** | `Bing.Auditing`（可选 `.Contracts`） | Dapper 支不支持 |
| **性能监测面板** | `Bing.MiniProfiler` | `net6.0` |
| **防止写错移植性 SQL** | `Bing.Data.Sql.Analyzers` | `BINGSQL002` 是 **Warning** 不是 Error，建议在 CI 提级 |

> 不知道选哪支 ORM？先看 [能力矩阵](能力矩阵.md)。入口名不确定？查 [架构文档 §12](../architecture/架构文档.md) 或 [使用文档 §3.3](使用文档.md)。

## 3. 各包 README 在哪

| 位置 | 内容 |
| --- | --- |
| `framework/src/<包名>/README.md` | 64 个框架包的 README（已内嵌进 nupkg，在 NuGet 包页面展示） |
| `components/src/<包名>/README.md` | 3 个业务组件包（含 `Bing.Biz.Payments`、`Bing.Biz.OAuthLogin`） |
| `docs/组件库文档.md` | 边缘包的详细用法（支付、OAuth、Exceptionless Sink、Mvc.UI、SkyAPM、EasyCaching、FreeRedis、两个 Analyzers） |
| `docs/横切能力文档.md` | 邮件、文本模板、锁、本地化、事件总线的详解 |

> ⚠ **`Bing.EventBus` 与 `Bing.EventBus.Abstractions` 是遗留包**（无人引用、`usedBy=0`），里面的 `ILocalEventBus` / `IDistributedEventBus` **不要在新代码里用**——现行的是 `Bing.Core` 的 `ISimpleEventBus` / `IMessageEventBus`。ABP 用户尤其容易踩这条。
>
> ⚠ **`Bing.Events.Cap.MySql`** 是 CAP 2.6 的源码镜像（换 MySqlConnector 以支持 FreeSQL），目前**无任何工程引用**。它与 `Bing.Events` 用的 CAP 8.0.1 差几个大版本，启用前请评估。
