## 1. 概述

Bing.NetCore 是一个基于 .NET 平台的**应用开发框架**，目标是提升中小型团队的交付效率。它由以下部分组成：

- **公共工具与基础能力**（模块系统、约定式依赖注入、反射查找、异常体系、时钟、本地化等）
- **DDD 分层基类**（实体 / 聚合根 / 值对象、仓储、工作单元、应用服务、查询对象）
- **多 ORM 数据访问**（EntityFrameworkCore / FreeSQL / Dapper，统一抽象 + 多数据库方言）
- **ASP.NET Core 集成**（模块化启动、统一 API 响应、JWT、多租户、AOP）
- **横切能力**（缓存、日志、事件总线、邮件、文本模板、分布式锁、对象映射、审计）

### 1.1 技术栈与版本

| 维度 | 说明 |
| --- | --- |
| 构建 SDK | `global.json` 固定为 **.NET SDK 8.0.424** |
| 类库目标框架 | `netstandard2.0`（默认，见 `framework.props` → `common.props`） |
| 应用/Web 层目标框架 | `net6.0`（如 `Bing.AspNetCore.*`、`Bing.Permissions`、`Bing.Events`、admin 模块） |
| ORM | EntityFrameworkCore 6、FreeSQL 3.2、Dapper 2.1 |
| AOP | AspectCore |
| 事件总线 | DotNetCore.CAP 8.0.1 |
| 对象映射 | AutoMapper |
| 日志 | Serilog / Exceptionless |
| JSON | Newtonsoft.Json（Web 层默认配置） |

> 说明：仓库根 `README.md` 的“开发环境”章节仍写着旧版 SDK v2.2，实际构建以 `global.json` 为准（SDK 8.0.424，运行库面向 net6.0）。

### 1.2 适用场景

适合需要**快速搭建分层清晰的后台服务 / Web API** 的团队：希望用现成的实体基类、仓储、工作单元、统一响应、JWT、多租户、审计等能力，把精力集中在业务领域建模上。

## 3. 快速开始（最小 Web API）

下面以一个最小 Web API 项目演示引导流程（参考 `samples/Bing.Samples.WebApi`）。

### 3.1 Program.cs

```csharp
using Bing.Samples.WebApi.Modules;

var builder = WebApplication.CreateBuilder(args);

// 1) 引入 Bing 框架并加载模块
builder.Services.AddBing()
    .AddModule<AppModule>();

var app = builder.Build();

// 2) 启用模块（装配中间件管道）
app.UseBing();

app.Run();
```

### 3.2 定义应用模块

```csharp
using System.ComponentModel;
using Bing.AspNetCore;
using Bing.Core.Modularity;

[Description("应用程序模块")]
[DependsOnModule(typeof(AspNetCoreModule))]   // 声明依赖：先启动 ASP.NET Core 基础模块
public class AppModule : AspNetCoreBingModule
{
    // 级别越小越先启动（Core < Framework < Application < Business）
    public override ModuleLevel Level => ModuleLevel.Application;

    public override IServiceCollection AddServices(IServiceCollection services)
    {
        services.AddControllers();
        return services;
    }

    public override void UseModule(IApplicationBuilder app)
    {
        app.UseRouting();
    }
}
```

两行即可完成框架接入：

- `services.AddBing()`：注册核心服务并创建 `IBingBuilder`，随后用 `.AddModule<T>()` 按依赖顺序加载模块。
- `app.UseBing()`：遍历已加载模块，依次执行 `UseModule`（ASP.NET 模块走 `UseModule(IApplicationBuilder)`）。

> 非 Web 场景（控制台 / WinForm）：`services.AddBing();` 后，`serviceProvider.UseBing();` 即可启动模块。

### 3.3 常用注册入口速查（精简）

上手时最常用的注册入口一览（按场景分类）。**完整清单见《架构文档》§12**——那里含每个入口的命名空间、完整重载签名，以及「不存在的入口」防误用清单。

| 场景 | 入口方法 | 说明 |
| --- | --- | --- |
| 框架启动 | `services.AddBing(Action<BingOptions>)` | 框架总入口，注册核心服务 + `BingCoreModule` / `DependencyModule` |
| 加载模块 | `.AddModule<T>()`（`IBingBuilder` 扩展） | 递归拉入 `[DependsOnModule]` 依赖并立即 `AddServices` |
| 启动模块 | `app.UseBing()` / `serviceProvider.UseBing()` | 分别为 Web / 非 Web（控制台、WinForm）场景 |
| MVC | `AddControllers(o => o.AddBing(services))` | 注入 Bing 模型绑定器与输出格式化器 |
| EF Core | `AddSqlServerUnitOfWork<T,TImpl>(connection, ...)`、`AddMySqlUnitOfWork<,>`、`AddOracleUnitOfWork<,>`、`AddSqliteUnitOfWork<,>` | 注册 DbContext 工作单元 + `IUnitOfWork` |
| EF Core（PgSQL） | **`AddPgSqlUnitOfWork<,>(...)`** | ⚠️ 不是 `AddPostgreSqlUnitOfWork` |
| FreeSQL | `AddMySqlUnitOfWork<T,TImpl>(connection, ...)`（`Bing.FreeSQL` 命名空间） | ⚠️ 与 EF 的同名方法是**两个不同方法**，参数签名不同 |
| Dapper Provider | `AddSqlServerProvider()` / `AddMySqlProvider()` / `AddPostgreSqlProvider()` / `AddOracleProvider()` / `AddSqliteProvider()` | 内部自动调用 `AddSqlCore()` |
| Dapper 数据源 | `AddSqlDataSource(key, DatabaseType, connectionString, providerKey: "bing.sqlserver")` | 多 Provider 时必须用具名数据源 |
| JWT 认证 | `AddJwt(configuration)` | 读配置节 **`JwtOptions`**，策略名 **`"jwt"`** |
| 事件总线 | `AddCapEventBus(...)` / `AddDefaultEventBus()` / `AddDomainEventDispatcher(...)` | 分布式 CAP / 进程内 / 领域事件分发 |
| 对象映射 | `AddAutoMapper()` | 扫描 `IObjectMapperProfile`，注册单例 `IObjectMapper` |
| 日志 | `AddBingLogging(Action<BingLoggingOptions>)` | `ILogFactory` / `ILog<>` |
| 本地化 | `AddJsonLocalization(...)` / `AddStoreLocalization<TStore>(...)` | JSON 文件 / 自定义存储型 |
| 邮件 | `AddMailKit(Action<EmailOptions>)` / `AddSmtpEmail(Action<EmailConfig>)` | MailKit / Smtp 实现 |
| 分布式锁 | `AddRedisDistributedLock()` / `AddLocalLock()` | Redis 锁（需先 `RedisHelper.Initialization`）/ 进程内锁 |
| AOP | **`EnableAop(Action<IAspectConfiguration>)`** | ⚠️ 启用 AOP 的入口叫 `EnableAop`，**没有 `AddAop`** |
| 中间件 | `UseBingExceptionHandling()` / `UseRealIp(...)` / `UseRequestResponseLog(app)` / `UseCorrelationId(app)` / `UseBingSerilogEnrichers(app)` | 异常、真实 IP、请求响应日志、链路标识、Serilog 增强 |
| 缓存 | ⚠️ **无内置注册入口** | 需 `RedisHelper.Initialization(...)` 后手工 `services.AddScoped<ICache, CSRedisCacheManager>()`，详见 §8.1 |
| 第三方 OAuth 登录 | ⚠️ **无内置注册入口** | `Bing.Biz.OAuthLogin`（16 个提供方）需手动 `new XxxAuthorizationConfigProvider` + `XxxAuthorizationProvider`，详见 [组件库文档 §2](../guides/组件库文档.md) |
| 支付 | `AddPay(Action<PayOptions>)` / `AddPay<TAlipay,TWechat>()` / `AddAlipay<T>()` / `AddWechatpay<T>()`（`Bing.Biz.Payments.Extensions`） | ⚠️ 返回 `void`，**不能链式调用**；包在 `components/src` |
| Razor → HTML | `AddRazorHtml()`（`Bing.AspNetCore.Mvc.UI.Extensions`） | 注册 `IRazorHtmlGenerator` / `IRouteAnalyzer` |
| Exceptionless 日志 | 🔌 **`WriteTo.Exceptionless(...)`** | 挂在 **Serilog** 的 `LoggerSinkConfiguration` 上，**不是** `services.AddXxx` |
| SQL 链路追踪 | 🔌 **`AddSqlQuery()`** | 挂在 **SkyAPM** 的 `SkyApmExtensions` 上，**不是** `services.AddXxx` |

> 五个最容易踩的坑：① AOP 入口是 `EnableAop` 而非 `AddAop`；② EF PostgreSQL 是 `AddPgSqlUnitOfWork` 而非 `AddPostgreSqlUnitOfWork`；③ 缓存没有 `AddCache`，必须手工注册；④ `AddPay` 系列返回 `void` 不能链式；⑤ Exceptionless / SkyAPM 的入口不在 `IServiceCollection` 上。
>
> 支付、Exceptionless、SkyAPM、RazorHtml 等 8 个包的完整说明见《[组件库文档](../guides/组件库文档.md)》。

## 4. 核心概念

### 4.1 模块化系统（Module System）

框架采用“模块化”启动范式（设计上参考 ABP 的 `IModule`）：

- `IBingModule` / `BingModule`（`Bing.Core.Modularity`）：模块契约，`Level` / `Order` / `Enabled` + 两阶段生命周期 `AddServices(IServiceCollection)` 与 `UseModule(...)`。
- `AspNetCoreBingModule`（`Bing.AspNetCore`）：Web 模块的基类，提供 `UseModule(IApplicationBuilder app)`。
- `[DependsOnModule(typeof(XxxModule))]`：声明模块依赖，`BingBuilder` 会递归拉入并按 `ModuleLevel`（Core=1 → Framework=10 → Application=20 → Business=30）排序启动。
- `ModuleLevel` 枚举控制启动顺序。

### 4.2 约定式依赖注入（自动注册）

只要类型实现以下标记接口之一，就会被自动扫描并注册，无需手写 `services.AddXxx`：

- `ISingletonDependency`（单例）
- `IScopedDependency`（作用域）
- `ITransientDependency`（瞬时）

用 `[Dependency(ServiceLifetime, TryAdd, ReplaceExisting, AddSelf)]` 可精细控制注册方式（如 `TryAdd=true` 表示默认实现、可被覆盖；`ReplaceExisting=true` 表示强制替换）。接口基类型通常用 `[IgnoreDependency]` 避免被约定注册。

### 4.3 统一 API 响应

框架**没有** `UnifyResult` / `IResult` / `[Result]` 这类类型/特性。真实机制是：

- `ApiResult : JsonResult`（`Bing.AspNetCore.Mvc`）：属性 `Code` / `Message` / `Data` / `OperationTime`。`StatusCode` 枚举：`Ok=1`、`Fail=2`、`Unauthorized=401`。静态方法 `ApiResult.Success(...)` / `ApiResult.Fail(...)`。
- `ResultHandlerAttribute : ResultFilterAttribute`：全局结果过滤器，把 `ObjectResult/JsonResult/EmptyResult/BadRequestObjectResult/ValidationFailedResult` 统一包成 `ApiResult`。已返回 `ApiResult` 或标注 `[IgnoreResultHandler]` 的控制器/Action 跳过包装。
- `IResultFactory : ISingletonDependency`：自定义结果形状（实现并注册后，`Success/Fail` 将使用你的工厂产出）。
- `BingControllerBase.Success(data, message, statusCode)` / `Fail(...)`：控制器内直接调用返回。

成功响应示例：

```json
{ "Code": 1, "Message": "操作成功", "OperationTime": "2026-09-17 19:10:55", "Data": { ... } }
```

### 4.4 异常处理

- 自定义异常类型位于 `Bing.Core`：`BingException`、`BusinessException`、`UserFriendlyException`、`Bing.Exceptions.Warning`（实现 `IHasErrorCode` / `IHasHttpStatusCode`）。
- `BingExceptionHandlingMiddleware`（`Bing.AspNetCore`，管道级）与 `BingExceptionFilter`（`Bing.AspNetCore.Mvc`，Action 级）：把异常转成 `{ "code": ..., "message": "..." }` 并在响应头加 `Bing-Error-Format: true`。
- `DefaultExceptionToErrorInfoConverter`：识别 `Warning` / `BusinessException` / `ConcurrencyException` / `EntityNotFoundException` 等并生成错误码与提示；生产环境默认不暴露堆栈。

典型用法：

```csharp
throw new BusinessException("1001", "余额不足");
// 或
throw new Warning("找不到对应的记录");
```

### 4.5 当前用户与多租户

- `ICurrentUser`（`Bing.Security.Users`）：`IsAuthenticated` / `UserId` / `UserName` / `TenantId` / `Roles` / `FindClaim` / `IsInRole`。控制器中可直接用 `CurrentUser.GetTenantCode()` 取租户编码。
- `ICurrentTenant`（`Bing.MultiTenancy`）：`IsAvailable` / `Id` / `Name` / `Change(id, name)`。基于 `AsyncLocal` 在当前请求内切换。

## 5. 分层架构与 DDD

### 5.1 实体 / 聚合根 / 值对象（`Bing.Ddd.Domain`）

| 类型 | 命名空间 | 说明 |
| --- | --- | --- |
| `EntityBase<TEntity>` / `EntityBase<TEntity,TKey>` | `Bing.Domain.Entities` | 实体基类，默认 `Guid` 主键，基于标识的相等性；`Init()` 在缺标识时生成 `Guid` |
| `AggregateRoot<TEntity>` / `AggregateRoot<TEntity,TKey>` | `Bing.Domain.Entities` | 聚合根，含 `AddDomainEvent/GetDomainEvents`；`AggregateRoot` 额外带乐观锁 `byte[] Version` |
| `FullAuditedAggregateRoot<TEntity,TKey>` 等 | `Bing.Domain.Entities.Auditing` | 叠加创建/修改/删除审计字段（来自 `Bing.Auditing`） |
| `ValueObjectBase<TValueObject>` | `Bing.Domain.Values` | 值对象，基于公共属性做相等性比较 |

### 5.2 仓储与存储（接口在领域层，实现在基础设施层）

> 注意：`IRepository` / `IStore` / `IQueryStore` / `IQueryRepository` **定义于 `Bing.Ddd.Domain`**（命名空间 `Bing.Data` / `Bing.Domain.Repositories`），不在 `Bing.Data`。

- `IRepository<TEntity,TKey> : IQueryRepository, IStore`：完整仓储 = 查询 + 写入 + `GetUnitOfWork()`。
- `IQueryRepository<TEntity,TKey>`（`Bing.Data`）：只读契约。
- `ICompactRepository<TEntity,TKey>`：精简仓储（`Find/FindByIds/Exists/Add/Update/Remove`）。
- `IQueryStore<TEntity,TKey> : IScopedDependency`：`Find/FindById/FindByIds/FindAll/Exists/Count`。
- `IStore<TEntity,TKey> : IQueryStore`：增加 `Add/Update/Remove`（参数标注 `[Valid]`，由 AOP 触发校验）。

### 5.3 工作单元与提交

- `IUnitOfWork : IDisposable`（`Bing.Uow`）：`Commit()` / `CommitAsync()`。
- `IUnitOfWorkManager`：聚合多个 UoW 统一提交。
- 提交时机有两种：
  1. **显式提交**：应用服务中 `await UnitOfWork.CommitAsync();`
  2. **AOP 自动提交**：在应用服务方法上标注 `[UnitOfWork]`，方法成功后由 `IUnitOfWorkManager.CommitAsync()` 统一提交（`CrudAppServiceBase` 的 `CreateAsync/UpdateAsync/SaveAsync` 已内置 `[UnitOfWork]`）。

### 5.4 查询对象与规格（`Bing.Data`）

- `IQueryParameter` / `QueryParameter`：查询参数基类，含 `Keyword`、`Page`、`PageSize`、`Order`。
- `IQuery<TEntity>` / `Query<TEntity>`：查询对象（规格模式），提供 `Where` / `WhereIf` / `WhereIfNotEmpty` / `Between` / `OrderBy` / `And` / `Or`。
- `ICondition<TEntity>` 与 `*Condition`（如 `AndCondition` / `OrCondition` / `IntSegmentCondition` / `DateTimeSegmentCondition`）：可组合的查询条件。
- `Pager` / `PagerList<T>`：分页与分页结果集合。

```csharp
var query = new Query<User>()
    .WhereIfNotEmpty(u => u.Name.Contains(keyword))
    .OrderBy(u => u.CreationTime, desc: true);
```

### 5.5 应用服务（`Bing.Ddd.Application`）

| 基类 | 注入 | 自带能力 |
| --- | --- | --- |
| `AppServiceBase` | `ILazyServiceProvider` / `ICurrentUser` / `ILog` | 通用基类，自行写 CRUD |
| `QueryAppServiceBase<TEntity,TDto,TQuery,TKey>` | `IQueryStore<TEntity,TKey>` | `GetByIdAsync` / `GetAllAsync` / `QueryAsync` / `PagerQueryAsync` |
| `DeleteAppServiceBase<...>` | `IUnitOfWork` + `IStore<TEntity,TKey>` | `DeleteAsync(ids)` |
| `CrudAppServiceBase<...>` | `IUnitOfWork` + `IRepository<TEntity,TKey>` | 上述全部 + `CreateAsync` / `UpdateAsync` / `SaveAsync` |

契约接口在 `Bing.Ddd.Application.Contracts`：`IAppService`、`ICrudAppService`、`IQueryAppService<TDto,TQuery>`、`DtoBase` / `RequestBase`、`[UnitOfWork]`。

DTO 与实体之间通过 `Bing.ObjectMapping`（`IObjectMapper` + AutoMapper）互相转换，典型写法 `request.MapTo<Entity>()`。

### 5.6 完整 CRUD 示例

**方式 A：继承 `CrudAppServiceBase`（框架标准化 CRUD）**

```csharp
public class ApplicationAppService : CrudAppServiceBase<Application, ApplicationDto, ApplicationQuery>
{
    public ApplicationAppService(IUnitOfWork uow, IRepository<Application, Guid> repository)
        : base(uow, repository) { }
}
// 自动获得 CreateAsync/UpdateAsync/SaveAsync/DeleteAsync + GetByIdAsync/QueryAsync/PagerQueryAsync
```

**方式 B：继承 `AppServiceBase` 手写（admin 模块实际采用，更灵活）**

```csharp
public class ApplicationService : AppServiceBase, IApplicationService
{
    protected IAdminUnitOfWork UnitOfWork { get; set; }
    protected IApplicationRepository ApplicationRepository { get; set; }

    public ApplicationService(IAdminUnitOfWork unitOfWork, IApplicationRepository repository)
    {
        UnitOfWork = unitOfWork;
        ApplicationRepository = repository;
    }

    public async Task<Guid> CreateAsync(CreateApplicationRequest request)
    {
        var entity = request.MapTo<Application>();   // DTO -> 实体
        entity.Init();                               // 生成主键
        await ApplicationRepository.AddAsync(entity);
        await UnitOfWork.CommitAsync();              // 显式提交
        return entity.Id;
    }

    public async Task DeleteAsync(string ids)
    {
        var entities = await ApplicationRepository.FindByIdsAsync(ids);
        await ApplicationRepository.RemoveAsync(entities);
        await UnitOfWork.CommitAsync();
    }
}
```

> admin 模块的领域仓储接口放在领域层（如 `IApplicationRepository : ICompactRepository<Application>`），不依赖任何 ORM；实现放在 `Bing.Admin.Data.EFCore`（如 `ApplicationRepository : CompactRepositoryBase<Application, ApplicationPo>, IApplicationRepository`）。

## 6. 数据访问

> 本节讲**怎么用**每一支。若你还不确定该选哪一支，先看 [《能力矩阵》](能力矩阵.md)——三种 ORM 在 18 个能力维度上的对照总表、场景推荐与混用注意事项。

### 6.1 EntityFrameworkCore（全功能 ORM）

运行时命名空间为 `Bing.Datas.EntityFramework.Core`（注意是 **Datas**），包名仍为 `Bing.EntityFrameworkCore`。

**定义工作单元**（继承对应库的 `XxxUnitOfWorkBase`）：

```csharp
public class AdminUnitOfWork : MySqlUnitOfWorkBase, IAdminUnitOfWork
{
    public AdminUnitOfWork(DbContextOptions options, IServiceProvider sp = null) : base(options, sp) { }
}
```

**注册**（各数据库提供程序暴露 `AddXxxUnitOfWork<TService, TImpl>(connectionString, ...)`）：

```csharp
// SqlServer
services.AddSqlServerUnitOfWork<IAdminUnitOfWork, AdminUnitOfWork>(
    "Server=.;Database=Admin;User Id=sa;Password=xxx;",
    dataConfigAction: cfg => { /* DataConfig */ });

// MySql / PostgreSql / Oracle / Sqlite 同构：
// services.AddMySqlUnitOfWork<...>(...);
// services.AddPostgreSqlUnitOfWork<...>(...);
// services.AddOracleUnitOfWork<...>(...);
// services.AddSqliteUnitOfWork<...>(...);
```

特点：`UnitOfWorkBase : DbContext`，含软删除全局过滤（`ISoftDelete`）、`IVersion` 乐观锁、审计属性注入（`IAuditPropertySetter`）、`ITransactionActionManager` 事务提交。实体映射通过 `IMap` / `MapBase`（如 `AggregateRootMap<T>`）。

### 6.2 FreeSQL（全功能 ORM，结构与 EF 对称）

当前仅提供 **MySql** 提供程序。同样实现 `IRepository` / `IStore` / `IUnitOfWork`。

```csharp
services.AddMySqlUnitOfWork<IMyUow, MySqlUnitOfWork>(
    "Data Source=...;User Id=...;Password=...;",
    setupAction: (sp, builder) => { /* FreeSqlBuilder 配置 */ },
    freeSqlSetupAction: (sp, orm) => { /* IFreeSql 配置 */ });
```

`UnitOfWorkBase : FreeSql DbContext`，含 `Aop.AuditValue`（乐观锁/创建修改时间/创建修改人）、软删除全局过滤。

### 6.3 Dapper + Bing.Data.Sql（高性能原始 SQL 引擎）

Dapper 集成**不提供**领域层仓储 / 工作单元，而是把 `Bing.Data.Sql` 的流利 SQL 引擎落地为可执行的 `ISqlQuery` / `ISqlExecutor`。多由 EF Core / FreeSQL 在需要原始 SQL 时复用。

**注册**：

```csharp
services.AddSqlServerProvider();                              // 注册方言/构建器/执行器/连接工厂
services.AddSqlDataSource("default", DatabaseType.SqlServer, connStr);
// 多库并存：再 AddMySqlProvider() + AddSqlDataSource("mysql", DatabaseType.MySql, ...)
services.AddBing();
```

**使用（流利 SQL）**：

```csharp
public class SqlServerQueryTest
{
    private readonly ISqlQuery _sqlQuery;
    public SqlServerQueryTest(ISqlQuery sqlQuery) => _sqlQuery = sqlQuery;

    public async Task<List<Row>> RawAsync() =>
        await _sqlQuery.Sql("Select Code,Amount From dbo.BingSqlBatch")
            .ToListAsync<Row>();

    public async Task<int> SelectOneAsync() =>
        await _sqlQuery.Query()
            .AppendSelect("1")
            .AppendFrom("(Select 1 as Value) t")
            .ScalarAsync<int>();

    public async Task<List<User>> QueryAsync(string name) =>
        await _sqlQuery.Query()
            .Select<User>()
            .WhereIfNotEmpty(u => u.Name.Contains(name))
            .OrderBy(u => u.Id)
            .Page(new Pager(1, 20))
            .ToListAsync<User>();
}
```

`Bing.Data.Sql` 提供的 API 表面（命名空间 `Bing.Data.Sql`）：`Select` / `From` / `Join` / `LeftJoin` / `Where` / `WhereIfNotEmpty` / `In` / `Between` / `GroupBy` / `OrderBy` / `Page` / `Skip` / `Take`，并以 `ToListAsync` / `FirstAsync` / `SingleAsync` / `ScalarAsync` / `ExecuteAsync` 终结执行。多数据库支持集中在 `IDialect`（标识符/参数前缀/分页语法）与 `ISqlProvider`（执行画像）两个扩展点。

### 6.4 如何选择

| 维度 | EntityFrameworkCore | FreeSQL | Dapper + Bing.Data.Sql |
| --- | --- | --- | --- |
| 本质 | 全功能 ORM | 全功能 ORM | 微型 ORM + SQL 执行引擎 |
| 仓储/存储 | ✅ | ✅ | ❌（用 `ISqlQuery` 或自建） |
| 工作单元 | ✅（`DbContext`） | ✅（`FreeSql DbContext`） | ❌（连接/事务作用域） |
| 注册入口 | `AddSqlServerUnitOfWork` 等 | `AddMySqlUnitOfWork` | `AddSqlServerProvider` + `AddSqlDataSource` |
| 多库 | 5 个 Provider | 仅 MySql | 5 个 Provider（含方言/执行器） |
| 适用 | 变更跟踪、迁移、LINQ | 偏好 FreeSQL 的团队 | 高性能、手写 SQL、跨库方言 |

三者共用底层：`Bing.Ddd.Domain`（抽象）、`Bing.Data`（查询对象）、`Bing.Data.Sql`（流利 SQL 与方言）、`Bing.Uow`（IUnitOfWork）。

### 7.1 控制器基类

| 基类 | 路由 / 特性 |
| --- | --- |
| `BingControllerBase : ControllerBase` | 提供 `Success/Fail` |

### 7.2 JWT 认证

`appsettings.json`：

```json

  "JwtOptions": {
    "Secret": "your-256bit-secret-key",
    "Issuer": "bing_identity",
    "Audience": "bing_client",
    "AccessExpireMinutes": 60,

    "ThrowEnabled": false,

  }

```

```csharp

services.AddJwt(Configuration);
```

### 7.3 多租户

- 解析贡献者链（`BingTenantResolveOptions.TenantResolvers`）：`CurrentUserTenantResolveContributor` → `Header` / `QueryString` / `Route` / `Domain` / `Cookie`（来自 `Bing.AspNetCore.MultiTenancy`）。
- 中间件 `MultiTenancyMiddleware`：解析出 `TenantConfiguration` 后调用 `ICurrentTenant.Change(id, name)` 切换。

> 仓库未提供 `UseMultiTenancy` 便捷扩展，需手动 `app.UseMiddleware<MultiTenancyMiddleware>()` 并在模块 `UseModule` 中注册；域名解析可用 `BingTenantResolveOptionsExtensions.AddDomainTenantResolver(options, "{0}.yourhost.com")`。

### 7.4 AOP（AspectCore）


## 10. 进阶提示

- **约定优先**：尽量用 `IScopedDependency` 等标记接口自动注册，避免手写 `services.AddXxx`；仅在需要控制生命周期/替换实现时用 `[Dependency(...)]`。
- **统一响应**：优先用 `QueryControllerBase` / `CrudControllerBase` + `Success(...)`，全局 `ResultHandlerAttribute` 负责包装；需自定义响应形状实现 `IResultFactory`。
- **提交边界**：简单场景用 `[UnitOfWork]` 自动提交；复杂多仓储操作用显式 `UnitOfWork.CommitAsync()`。
- **多库并存**：不同库用不同 Provider 的 `AddXxxUnitOfWork` / `AddXxxProvider` + `AddSqlDataSource(name, ...)` 区分；`ISqlProviderRuntime` 按 `DatabaseType` 路由。
- **扩展点一览**：自定义模块（`[DependsOnModule]`）、自定义仓储/工作单元（继承 `XxxUnitOfWorkBase` / `RepositoryBase`）、自定义结果工厂（`IResultFactory`）、自定义异常转换（`IExceptionToErrorInfoConverter`）、自定义本地化/模板引擎/缓存提供器、新增数据库方言（`IDialect` + `ISqlProvider`）。详见《设计思路文档》。
