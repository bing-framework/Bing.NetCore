## 1. 邮件

三个工程，两套实现：

| 工程 | 命名空间 | 角色 |
| --- | --- | --- |
| `Bing.Emailing` | `Bing.Emailing` | **抽象 + Smtp 实现**：`IEmailSender`、`EmailConfig`、`附件`、`邮件队列` |
| `Bing.Emailing` | `Bing.Emailing.Smtp` | `ISmtpEmailSender` / `SmtpEmailSender`（基于 `System.Net.Mail.SmtpClient`） |
| `Bing.MailKit` | `Bing.MailKit` | `IMailKitEmailSender` / `MailKitEmailSender`（基于 MailKit，**推荐**） |

### 1.1 两个注册入口（都在，但命名空间不同）

```csharp
// ① MailKit（推荐）—— 在 Bing.MailKit 命名空间下
using Bing.MailKit.Extensions;
services.AddMailKit(o =>
{
    o.EmailConfig.Host = "smtp.example.com";
    o.EmailConfig.Port = 465;
    o.EmailConfig.UserName = "user";
    o.EmailConfig.Password = "***";
    o.MailKitConfig.SecureSocketOption = SecureSocketOptions.SslOnConnect;
});

// ② Smtp（System.Net.Mail）—— 在 Bing.Emailing.Smtp 命名空间下
using Bing.Emailing.Smtp;
services.AddSmtpEmail(o => { o.Host = "smtp.example.com"; /* ... */ });
```

⚠ **三个易混淆点**：

| 坑 | 说明 |
| --- | --- |
| `AddMailKit` 有两个版本 | `Bing.MailKit.Extensions` 下的 `AddMailKit(Action<EmailOptions>)` 与 `AddMailKit<TEmailConfigProvider, TMailKitConfigProvider>()`；**另有**一个 `AddMailKit<TEmailConfigProvider>()` 在 **`Bing.Emailing.Smtp`** 命名空间下，它注册的是 `ISmtpEmailSender`（走 System.Net.Mail），**不是** MailKit。using 写错就会拿到另一套实现 |
| 返回值是 `void` | 三个 `AddXxx` 都返回 `void`，**不能链式调用** |
| 用的是 `TryAdd*` | 重复注册不会覆盖，先注册者生效 |

### 1.2 关键类型

| 类型 | 说明 |
| --- | --- |
| `IEmailSender` | 发送抽象（`SendAsync`），`EmailSenderBase` 是基类，`NullEmailSender` 是空实现兜底 |
| `EmailConfig` / `IEmailConfigProvider` / `DefaultEmailConfigProvider` | 邮箱配置与配置提供器 |
| `EmailBox` | 收/发件人封装 |
| `IAttachment` / `MemoryStreamAttachment` / `PhysicalFileAttachment` | 附件抽象与两种实现（内存流 / 物理文件） |
| `IMailQueueManager` / `MailQueueManagerBase` / `SmtpMailQueueManager` / `MailKitMailQueueManager` | **邮件队列**：先把邮件入队，再由后台任务发送 |
| `IMailQueueService` / `MailQueueService` / `IMailQueueProvider` / `MailQueueProvider` | 队列服务与队列源扩展点 |
| `IMailKitSmtpBuilder` / `DefaultMailKitSmtpBuilder` | MailKit 的 `SmtpClient` 构建器（想自定义连接参数就替换它） |

### 1.3 什么时候用队列

`IEmailSender.SendAsync` 是**同步阻塞式发送**（等 SMTP 往返）。在请求线程里发邮件会拖慢响应，两种做法：

1. 注入 `IMailQueueManager`，把邮件入队，交给自己的后台任务（参考 [Hangfire 样例](../../samples/Bing.Samples.Hangfire/README.md)）；
2. 自己包一层 `IHostedService` / `IEventBus` 异步处理。

> 框架**没有**内置"自动后台发送"的开箱实现——`IMailQueueManager` 只负责存取队列，调度要你自己接。

## 2. 文本模板

| 工程 | 命名空间 | 说明 |
| --- | --- | --- |
| `Bing.TextTemplating` | `Bing.TextTemplating` | 模板抽象：定义、内容提供、渲染引擎、渲染器 |
| `Bing.TextTemplating.Scriban` | `Bing.TextTemplating.Scriban` | Scriban 引擎实现 |

### 2.1 ⚠ 没有注册入口

整个 `Bing.TextTemplating` 工程里**没有一处 `IServiceCollection` 扩展**，架构文档 §12 里也查不到它。需要**手动装配**。

### 2.2 关键类型与扩展点

| 类型 | 说明 |
| --- | --- |
| `BingTextTemplatingOptions` | 总配置：`DefinitionProviders`（`ITypeList<ITemplateDefinitionProvider>`）、`ContentContributors`、`RenderingEngines`（`IDictionary<string, Type>`）、`DefaultRenderingEngine` |
| `ITemplateDefinitionProvider` / `TemplateDefinitionProviderBase` | **模板定义来源**：实现它来声明"有哪些模板" |
| `ITemplateDefinitionManager` / `TemplateDefinitionManager` | 汇总所有 Provider 的模板定义 |
| `ITemplateContentProvider` / `TemplateContentProvider` | **模板内容来源**：按模板名取模板正文（默认实现从定义里取，可换成数据库/文件） |
| `ITemplateContentContributor` / `TemplateContentContributorContext` | **渲染前的内容贡献者**（注入公共变量、布局片段等扩展点） |
| `ITemplateRenderingEngine` / `TemplateRenderingEngineBase` | 渲染引擎抽象 |
| `ScribanTemplateRenderingEngine` | Scriban 实现（`Bing.TextTemplating.Scriban`） |
| `ScribanTemplateDefinitionExtensions` | Scriban 侧的模板定义辅助扩展 |
| `ITemplateRenderer` / `BingTemplateRenderer` | 面向使用方的渲染门面 |

### 2.3 装配与使用要点

```csharp
// 1) 配置：登记模板定义 Provider、内容贡献者、渲染引擎与默认引擎
services.Configure<BingTextTemplatingOptions>(o =>
{
    o.DefinitionProviders.Add<MyTemplateDefinitionProvider>();
    o.RenderingEngines["Scriban"] = typeof(ScribanTemplateRenderingEngine);
    o.DefaultRenderingEngine = "Scriban";
});

// 2) 注册服务（无 AddXxx，需自行注册；构造签名以源码为准）
//    ITemplateDefinitionManager → TemplateDefinitionManager
//    ITemplateContentProvider   → TemplateContentProvider
//    ITemplateRenderer          → BingTemplateRenderer
//    ITemplateRenderingEngine   → ScribanTemplateRenderingEngine

// 3) 渲染
await templateRenderer.RenderAsync("WelcomeEmail", new { Name = "张三" });
```

> `RenderingEngines` 的**键名必须与模板定义里声明的引擎名一致**，`DefaultRenderingEngine` 非空时也必须是已注册的键之一，否则取不到引擎。

## 3. 锁

| 工程 | 入口 | 契约 | 实现 |
| --- | --- | --- | --- |
| `Bing.Core`（`Bing/Locks/`） | `AddLocalLock()` / `AddLocalLock<TLocalLock>()` | `ILock` | `LocalLock`（进程内） |
| `Bing.Locks.CSRedis` | `AddRedisDistributedLock()` / `AddRedisDistributedLock<TDistributedLock>()` | `IDistributedLock` | `CSRedisDistributedLock` |

- 两个入口都用 `TryAddSingleton`，**重复注册不覆盖**；
- `ILock` 与 `IDistributedLock` **不是继承关系**，是两套独立契约，别指望注入一个能顶两个；
- ⚠ **`AddRedisDistributedLock` 要求先完成 CSRedis 静态初始化**（`RedisHelper.Initialization(...)`），否则运行时拿不到 Redis 客户端；
- 泛型重载用于替换实现（如测试时换成内存锁）。

用法（与《使用文档》§8.6 一致）：

```csharp
await distributedLock.ExecuteWithLockAsync(
    "order:1", Guid.NewGuid().ToString(), TimeSpan.FromSeconds(30),
    async () => { /* 临界区 */ });
```

## 4. 本地化

| 入口 | 命名空间 | 说明 |
| --- | --- | --- |
| `AddJsonLocalization()` | `Bing.Localization` | 默认 `resourcesPath = "Resources"` |
| `AddJsonLocalization(resourcesPath)` | 同上 | 指定资源目录 |

## 5. 事件总线：两套并存，别选错

> **本节只覆盖"包"的选型**。框架里与"事件"相关的机制其实有**四套**（进程内事件 `ISimpleEventBus`、CAP 集成事件 `IMessageEventBus`、DDD 领域事件、遗留 `Bing.EventBus*`），其中**领域事件当前不会被派发**、`send:false` 在事务外会**静默丢事件**。完整对照、发布链路与选型决策树见 **[事件与消息文档](../architecture/事件与消息文档.md)**。

仓库里**同时存在** `Bing.EventBus`（旧）与 `Bing.Events`（新），这是最容易踩的坑。

### 5.1 选型

| 维度 | `Bing.EventBus` / `Bing.EventBus.Abstractions` | `Bing.Events` |
| --- | --- | --- |
| 状态 | **遗留**，架构文档标注"不使用" | **现行** |
| 引用情况 | 仓库内**只有 `Bing.EventBus.Tests` 引用它**；`Bing.EventBus.Abstractions` 无人引用 | `Bing.Admin.Infrastructure` 唯一生产引用者 + 自身测试 |
| TFM | netstandard2.0 | **net6.0** |
| CAP 版本 | 无 | `DotNetCore.CAP` **8.0.1** |
| 注册入口 | ⚠ **无**（需手工装配） | `AddDefaultEventBus()` / `AddCapEventBus(...)` |
| 主要契约 | `IEventBus` / `ILocalEventBus` / `IDistributedEventBus` / `IEventHandler` / `ILocalEventHandler` / `IDistributedEventHandler` / `IMessageEventBus` | `IEventBus` / `ISimpleEventBus` / `IMessageEventBus` / `IEventHandler<T>` |
| 实际使用 | ❌ 无生产使用者 | ✅ admin 用 `AddCapEventBus`（**⚠ 但 `AddDefaultEventBus` 全仓无调用者**） |

⚠ **两个包都有名为 `IMessageEventBus` / `IEventBus` 的类型**，只是命名空间不同（`Bing.EventBus` vs `Bing.Events`）。同时 using 会产生**歧义编译错误**——新代码一律只用 `Bing.Events`。

### 5.2 `Bing.EventBus` 里那些类型（了解即可，不要新用）

`LocalEventBus` / `NullLocalEventBus`、`ActionEventHandler`、`IEventHandlerFactory` → `IocEventHandlerFactory` / `TransientEventHandlerFactory` / `SingleInstanceHandlerFactory`、`EventHandlerDisposeWrapper`、`EventBusExtensions`。这是一套 ABP vNext 早期风格的事件总线，被 `Bing.Events` 取代。

### 5.3 `Bing.Events.Cap.MySql` —— 一个"当前无人引用"的包

| 项 | 值 |
| --- | --- |
| 路径 | `framework/src/Bing.Events.Cap.MySql/` |
| TFM | **`netstandard2.1`**（与仓库默认的 netstandard2.0 不同） |
| 内容 | `00-Source/` 下的 **CAP 早期官方 MySql 存储源码镜像**（`IStorageInitializer.MySql.cs` 等） |
| 用途（官方描述） | "CAP2.6 版本的源码，**升级 MySqlConnector**，用于支持 FreeSQL 使用" |
| 引用情况 | ⚠ **当前无任何工程引用**——唯一引用点在 `Bing.Admin.Data.FreeSQL.csproj` 里，且**被注释掉** |

它提供的是 CAP 的 `CapOptions` 扩展：

```csharp
// 与官方 CAP 同名同签名，但内部注册的是 MySqlCapOptionsExtension
o.UseMySql(connectionString);
o.UseMySql(opt => { opt.ConnectionString = connectionString; });

// 注意：这里的 UseEntityFramework<TContext> 也被"改写"成走 MySql 存储
o.UseEntityFramework<AdminUnitOfWork>();
```

**为什么要有它**：CAP 官方包用的 MySQL 驱动在 FreeSQL 场景下有冲突，这份镜像把驱动换成 MySqlConnector。

**要不要用**：

- 用 EF Core + CAP → 不需要，官方 `DotNetCore.CAP.MySql` / EF 存储即可；
- 用 **FreeSQL + MySQL + CAP** → 才可能需要它，此时要把 `Bing.Admin.Data.FreeSQL.csproj` 里那行注释掉的 `ProjectReference` 打开；
- ⚠ 它是 **CAP 早期版本的源码**，而 `Bing.Events` 用的是 **CAP 8.0.1**——**版本跨度很大，直接启用大概率需要适配**，启用前请先评估。
- ⚠ **该包内部版本标注自相矛盾**：`Bing.Events.Cap.MySql.csproj:9` 的 `Description` 声称是「CAP**2.6** 版本的源码」，而 `dependency.props:3` 实际 pin 的是 `DotNetCore.CAP` **3.1.2**。**按源码为准**，无论哪一个是真，都与 8.0.1 相差数个主版本。

### 5.4 CAP 出箱表落哪儿

见 [子系统深挖 §1](../architecture/子系统深挖.md) 与 [modules/admin README §6](../../modules/admin/README.md)：admin 用 `o.UseEntityFramework<AdminUnitOfWork>() + RabbitMQ`，出箱表落在 MySQL。

## 6. 缓存（补《使用文档》§8.1）

三个实现，成熟度差异很大：

| 实现 | 工程 | 状态 | 注册 |
| --- | --- | --- | --- |
| `CSRedisCacheManager` | `Bing.Caching.CSRedis` | ✅ **实际在用**（admin 使用） | ⚠ 无 `AddXxx`：先 `RedisHelper.Initialization(new CSRedisClient(connStr))`，再 `services.AddScoped<ICache, CSRedisCacheManager>()` |
| `FreeRedisCacheManager` | `Bing.Caching.FreeRedis` | 🧩 可用但需手动装配 | 无 `AddXxx`：先注册 `RedisClient`，再 `services.AddSingleton<IRedisCache, FreeRedisCacheManager>()`（详见 [组件库文档 §5](组件库文档.md)） |
| `CacheManager`（EasyCaching） | `Bing.EasyCaching` | ⚠ **不可用** | `AddCaching` 整段被注释，`CachingOptions` 是 `internal`（详见 [组件库文档 §4](组件库文档.md)） |

**结论**：需要 Redis 缓存就用 **CSRedis** 那套；想换 FreeRedis 得自己装配；EasyCaching 目前不要依赖。

## 8. 常见坑

1. **`AddMailKit` 有两个"版本"在两套命名空间**——`Bing.MailKit.Extensions`（真 MailKit）与 `Bing.Emailing.Smtp`（System.Net.Mail）。using 决定你拿到哪个。
2. **邮件入口返回 `void`**——不能链式调用，且内部 `TryAdd`，重复注册无效。
3. **`Bing.TextTemplating` 没有 `AddXxx`**——不要照着别的模块找 `AddTextTemplating`。
4. **`AddRedisDistributedLock` 依赖 CSRedis 静态初始化**——漏了 `RedisHelper.Initialization` 会运行时炸。
5. **事件总线命名空间撞车**——`Bing.EventBus` 与 `Bing.Events` 都有 `IEventBus` / `IMessageEventBus`，同时 using 会歧义。只用 `Bing.Events`。
6. **`Bing.Events.Cap.MySql` 是 CAP 2.6 源码**——与 `Bing.Events` 用的 CAP 8.0.1 差了几个大版本，别默认它能直接开箱。
7. **缓存没有 `AddCache`**——三个实现都要手工注册，其中 EasyCaching 那个目前不可用。
