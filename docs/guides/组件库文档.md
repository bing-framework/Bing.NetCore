## 1. Bing.Biz.Payments — 支付宝 / 微信支付 ✅

| 项 | 值 |
| --- | --- |
| 路径 | `components/src/Bing.Biz.Payments/` |
| TFM | `netstandard2.0` |
| 命名空间 | `Bing.Biz.Payments`（子命名空间 `.Alipay.*` / `.Wechatpay.*` / `.Core` / `.Extensions`） |
| 注册入口 | `services.AddPay(...)` / `AddPay<TAlipay,TWechat>()` / `AddAlipay<T>()` / `AddWechatpay<T>()` |
| 依赖 | `Bing.Extensions`、`Microsoft.Extensions.Logging` |
| 规模 | ~100 个源文件，是 `components/` 里体量最大的包 |

> ⚠ **它在 `components/src`，不在 `framework/src`**——因此**不参与** docfx 的 API 元数据生成（配置见 `docs/docfx.json`），站点上查不到它的逐方法文档。

### 1.1 注册

```csharp
using Bing.Biz.Payments.Extensions;   // ← 必须：AddPay 在这个命名空间下的 static partial class Extensions

services.AddPay(o =>
{
    o.AlipayOptions = new AlipayConfig { /* AppId / 私钥 / 公钥 / 网关等 */ };
    o.WechatpayOptions = new WechatpayConfig { /* AppId / 商户号 / 密钥等 */ };
});
```

四个入口的区别：

| 入口 | 配置来源 | 注册内容 |
| --- | --- | --- |
| `AddPay(Action<PayOptions>)` | 直接传配置对象 | 两个 ConfigProvider（Singleton）+ `IPayFactory` + 支付宝 Notify/Return + 微信 Notify |
| `AddPay<TAlipayConfigProvider, TWechatpayConfigProvider>()` | 自定义 Provider 类型 | 同上，ConfigProvider 换成你的实现（Scoped） |
| `AddAlipay<TAlipayConfigProvider>()` | 自定义 Provider | 只注册支付宝侧（Factory + Notify + Return） |
| `AddWechatpay<TWechatpayConfigProvider>()` | 自定义 Provider | 只注册微信侧（Factory + Notify） |

⚠ **注意**：这四个方法返回值是 `void`，**不能链式调用**（与框架里多数 `AddXxx` 返回 `IServiceCollection` 的习惯不同）。

内部全部使用 `TryAdd*`，重复调用不会覆盖已有注册。

### 1.2 使用

注入 `IPayFactory`，按 `PayWay` 创建对应服务：

```csharp
public class PayService
{
    private readonly IPayFactory _payFactory;
    public PayService(IPayFactory payFactory) => _payFactory = payFactory;

    public async Task<string> PayAsync(PayWay way, PayParam param)
    {
        var service = _payFactory.CreatePayService(way);
        var result = await service.PayAsync(param);
        return result.Result;
    }
}
```

`IPayFactory` 的工厂方法一览：

| 渠道 | 方法 | 对应 `PayWay` |
| --- | --- | --- |
| 支付宝 | `CreatePayService(PayWay)` | `AlipayBarcodePay` / `AlipayQrCodePay` / `AlipayAppPay` / `AlipayPagePay` / `AlipayWapPay` |
| 支付宝 | `CreateAlipayNotifyService()` / `CreateAlipayReturnService()` | 回调通知 / 同步跳转 |
| 支付宝 | `CreateAlipayBarcodePayService()` / `CreateAlipayQrCodePayService()` / `CreateAlipayAppPayService()` / `CreateAlipayPagePayService()` / `CreateAlipayWapPayService()` | — |
| 微信 | `CreatePayService(PayWay)` | `WechatpayPaymentCodePay` / `WechatpayJsApiPay` / `WechatpayNativePay` / `WechatpayAppPay` / `WechatpayMiniProgramPay` / `WechatpayH5Pay` |
| 微信 | `CreateWechatpayNotifyService()` / `CreateWechatpayDownloadBillService()` / `CreateWechatpayBarcodePayService()` / `CreateWechatpayJsApiPayService()` / `CreateWechatpayAppPayService()` / `CreateH5PayService()` / `CreateWechatpayMiniProgramPayService()` | — |

`CreatePayService(PayWay)` 遇到未实现的 `PayWay` 会抛 `NotImplementedException`（异常消息取 `way.Description()`）。

### 1.3 目录结构

```
Alipay/    Abstractions（7 个服务契约）Configs Parameters Requests Results Services
Wechatpay/ Abstractions（9 个服务契约）Configs Enums Parameters Requests Results Services Signatures CsvMappings
Core/      IPayService PayParam PayResult RefundResult PayWay DownloadBillParam INotifyService
Factories/ PayFactory
Extensions/ Extensions.Service（注册入口） PayOptions
```

微信侧自带签名管理器（`Md5SignManager` / `HmacSha256SignManager` + `SignManagerFactory`）与账单 CSV 映射（`CsvMappings/`），不需要额外引三方库。

## 2. Bing.Biz.OAuthLogin — 第三方 OAuth 登录 🧩

| 项 | 值 |
| --- | --- |
| 路径 | `components/src/Bing.Biz.OAuthLogin/` |
| TFM | `netstandard2.0` |
| 命名空间 | `Bing.Biz.OAuthLogin`、`.Core`、`.{Provider}`、`.Extensions` |
| 注册入口 | **无** —— `IOAuthLoginFactory` 目前是**空接口**，包内没有任何 `IServiceCollection` 扩展 |
| 依赖 | `Bing.Exceptions`、`Bing.Validation` |
| 规模 | ~100 个源文件 / 16 个提供方，是 `components/` 里体量最大的包之一 |

### 2.1 支持的提供方（16 个）

`OAuthWay` 枚举（`Bing.Biz.OAuthLogin.Core`）与目录一一对应：

| 分组 | 提供方 |
| --- | --- |
| 国内社交 / 平台 | QQ、微信（`Wechat`）、新浪微博（`Weibo`）、钉钉（`DingTalk`）、百度（`Baidu`）、开源中国（`OsChina`） |
| 国内电商 / 云服务 | 淘宝（`Taobao`）、阿里巴巴（`Alibaba`）、京东（`Jd`）、有赞（`Youzan`）、美丽说（`MeiliShuo`） |
| 海外 | `Microsoft`、`Github`、`Facebook` |
| 开发者平台 | Coding.NET（`Coding`）、码云（`Gitee`） |

> ⚠ 这是**历史遗留的提供方清单**：部分平台（有赞、美丽说、开源中国等）的接口版本较旧，**对接前请自行验证目标平台的现行 OAuth 文档**，不要假设本包仍与其兼容。

### 2.2 核心类型

| 类型 | 位置 | 说明 |
| --- | --- | --- |
| `AuthorizationConfigBase` | `Core/` | 配置基类：`AppId` / `AppKey` / `CallbackUrl` / `AuthorizationUrl` / `AccessTokenUrl`，全部 `[Required]`；`Validate()` 失败抛 **`Warning`** |
| `AuthorizationConfigProviderBase<TConfig>` | `Core/` | 各提供方配置提供器基类（如 `QQAuthorizationConfigProvider : AuthorizationConfigProviderBase<QQAuthorizationConfig>`） |
| `IAuthorizationConfig` / `IAuthorizationConfigProvider` | `Core/` | 配置与配置提供器契约 |
| `IAuthorizationProvider` | `Core/` | 继承 `IAuthorizationUrlProvider<AuthorizationParam>` |
| `AuthorizationProviderBase` | `Core/` | 各提供方 Provider 基类（如 `QQAuthorizationProvider(IQQAuthorizationConfigProvider)`） |
| `AuthorizationParam` / `AuthorizationUserParam` / `AccessTokenParam` | `Core/` | 授权 / 取用户信息 / 取令牌的参数对象 |
| `AuthorizationResult` / `AccessTokenResult` / `AuthorizationUserInfoResult` | `Core/` | 结果对象 |
| `AuthorizationParameterBuilder` | `Core/` | 参数拼装 |
| `OAuthConst` / `OAuthWay` | `Core/` | 常量与提供方枚举 |
| `IOAuthLoginFactory` | 包根 | **当前是空接口**，没有实现，也**不提供**按 `OAuthWay` 创建 Provider 的工厂 |

能力接口（`Core/`）：`IAccessTokenProvider`、`IRefreshTokenProvider`、`IGetOpenIdProvider`、`IGetUserInfoProvider`、`IAuthorizationUrlProvider`。

### 2.3 用法（必须手动装配）

没有 `AddXxx`，需要自己构造并注册：

```csharp
using Bing.Biz.OAuthLogin.QQ;
using Bing.Biz.OAuthLogin.QQ.Configs;

// 1) 配置（AuthorizationUrl / AccessTokenUrl 由各 Provider 预置，通常不必填）
var config = new QQAuthorizationConfig
{
    AppId = configuration["OAuth:QQ:AppId"],
    AppKey = configuration["OAuth:QQ:AppKey"],
    CallbackUrl = "https://your.site/oauth/qq/callback"
};
config.Validate();   // 校验失败抛 Bing 的 Warning 异常

// 2) 配置提供器 → Provider
var configProvider = new QQAuthorizationConfigProvider(config);
var provider = new QQAuthorizationProvider(configProvider);

// 3) 注册进容器（生命周期自己定：配置单例、Provider 可 Scoped）
services.AddSingleton<IQQAuthorizationConfigProvider>(configProvider);
services.AddScoped<IQQAuthorizationProvider>(
    sp => new QQAuthorizationProvider(sp.GetRequiredService<IQQAuthorizationConfigProvider>()));
```

### 2.4 三步走流程

| 步骤 | 用什么 |
| --- | --- |
| ① 生成授权跳转地址 | `IAuthorizationUrlProvider<AuthorizationParam>`（由 `IAuthorizationProvider` 继承） |
| ② 回调里用 code 换 token | 扩展方法 `provider.GetTokenAsync(AccessTokenParam)`（`Bing.Biz.OAuthLogin.Extensions`） |
| ③ 用 token 取用户信息 / 刷新 | `IGetUserInfoProvider`；刷新用 `provider.RefreshTokenAsync(token)` |

两个扩展方法内部做**能力判定**：Provider 没实现对应能力接口时会抛 `NotImplementedException`——所以不是每家平台都支持刷新令牌。

结果转换：`AuthorizationResultExtensions`（`.Extensions`）提供 `ToQQToken()` / `ToWechatToken()` / `ToWeiboToken()`，把通用 `AuthorizationResult` 转成各家自己的令牌类型。

### 2.5 注意

- **不要找 `AddOAuth` / `AddOAuthLogin`**——本包没有任何注册入口，`IOAuthLoginFactory` 是空接口，形同占位。
- **与 `AddJwt` 是两回事**：本包只负责"向第三方平台换取身份"，拿到用户信息后**仍需你自己签发本站令牌**。
- `AuthorizationConfigBase.Validate()` 抛的是 Bing 自己的 **`Warning`** 异常（不是 `ValidationException`），捕获时别写错类型。
- 位于 `components/src`，**不在 docfx API 元数据范围**（同 `Bing.Biz` / `Bing.Biz.Payments`）。

## 4. Bing.EasyCaching — EasyCaching 缓存适配 ⚠

| 项 | 值 |
| --- | --- |
| 路径 | `framework/src/Bing.EasyCaching/` |
| TFM | `netstandard2.0` |
| 命名空间 | `Bing.EasyCaching` |
| 注册入口 | ⚠ **`AddCaching` 整段被注释**，当前不可用 |
| 依赖 | EasyCaching 1.9.2（Core / Bus.Redis / HybridCache / InMemory / Redis / Serialization.SystemTextJson）、`Bing.Caching` |

### 现状

- `Bing/EasyCaching/Extensions.Service.cs` **整个文件被注释**，`AddCaching(this IServiceCollection, Action<EasyCachingOptions>)` 编译不进去；
- `CachingOptions` 是 **`internal`** 类，它的 `AddRedisEndPoints(...)` / `GetRedisEndPoints()` / `Clear()` 静态方法**对外不可见**；
- 因此这个包目前**只提供了依赖清单，没有可用的 API 表面**。

### 想用的话

两条路：

1. **不用本包**：直接引 EasyCaching 官方包并 `services.AddEasyCaching(...)`，再自己实现 `ICache`（`Bing.Caching`）做适配；
2. **修复本包**：取消 `Extensions.Service.cs` 的注释，把 `CachingOptions` 改为 `public`（或把端点配置收进 `EasyCachingOptions` 委托里，避免 `internal` 静态集合带来的进程级状态污染）。

> 提醒：`CachingOptions._redisEndPoints` 是**进程级静态可变集合**，`Clear()` 还会把它置为 `null`。即使修好了入口，并发配置与重复初始化也存在隐患，建议顺手重构。

## 5. Bing.Caching.FreeRedis — FreeRedis 缓存实现 🧩

| 项 | 值 |
| --- | --- |
| 路径 | `framework/src/Bing.Caching.FreeRedis/` |
| TFM | `netstandard2.0` |
| 命名空间 | `Bing.Caching.FreeRedis` |
| 注册入口 | **无** |
| 依赖 | `FreeRedis` 1.1.5、`Bing.Caching` |

只有一个类型：

```csharp
public class FreeRedisCacheManager : IRedisCache
{
    public FreeRedisCacheManager(RedisClient client) { /* ... */ }
}
```

**需要手动装配**——先注册 `RedisClient`，再注册管理器：

```csharp
services.AddSingleton(new RedisClient("127.0.0.1:6379,password=,defaultDatabase=0"));
services.AddSingleton<IRedisCache, FreeRedisCacheManager>();
// 如果希望 ICache 也解析到它：
services.AddSingleton<ICache>(sp => sp.GetRequiredService<IRedisCache>() as ICache
                                    ?? sp.GetRequiredService<IRedisCache>());
```

> `FreeRedisCacheManager` 实现了 `IRedisCache`（`Bing.Caching` 中 `ICache` 的 Redis 扩展接口）。注册前请确认 `IRedisCache` 与 `ICache` 的继承关系与你期望的解析目标一致，避免 `ICache` 解析到别的缓存实现。

## 6. Bing.Logging.Sinks.Exceptionless — Exceptionless 日志 🔌

| 项 | 值 |
| --- | --- |
| 路径 | `framework/src/Bing.Logging.Sinks.Exceptionless/` |
| TFM | `netstandard2.0` |
| 命名空间 | ⚠ **`Serilog`**（不是 `Bing.*`！） |
| 注册入口 | 🔌 `WriteTo.Exceptionless(...)`（Serilog Sink，不是 `IServiceCollection` 扩展） |
| 依赖 | `Bing.Logging`、Exceptionless、Serilog |

### 为什么找不到 `services.AddExceptionless`

因为入口挂在 **Serilog 的 `LoggerSinkConfiguration`** 上：

```csharp
namespace Serilog;                                   // ← 注意命名空间
public static partial class LoggerSinkConfigurationExtensions
{
    public static LoggerConfiguration Exceptionless(
        this LoggerSinkConfiguration loggerSinkConfiguration,
        string apiKey,
        Func<EventBuilder, EventBuilder> additionalOperation = null,
        bool includeProperties = true,
        LogEventLevel restrictedToMinimumLevel = LevelAlias.Minimum);

    public static LoggerConfiguration Exceptionless(
        this LoggerSinkConfiguration loggerSinkConfiguration,
        string apiKey, string serverUrl = null, string[] defaultTags = null,
        Func<EventBuilder, EventBuilder> additionalOperation = null,
        bool includeProperties = true,
        LogEventLevel restrictedToMinimumLevel = LevelAlias.Minimum);
    // 还有一个重载
}
```

### 用法（照抄 `samples/Bing.Samples.Hangfire`）

```csharp
services.AddBingLogging(x => { });
services.AddLogging(loggingBuilder =>
{
    var configuration = services.GetConfiguration();
    Log.Logger = new LoggerConfiguration()
        .Enrich.FromLogContext()
        .Enrich.WithLogLevel()
        .Enrich.WithSpan()
        .WriteTo.Exceptionless(additionalOperation: builder =>       // ← 这里
        {
            builder.Target.AddTags(TraceIdContext.Current?.TraceId ?? string.Empty);
            return builder;
        })
        .ReadFrom.Configuration(configuration)
        .ConfigLogLevel(configuration)
        .CreateLogger();
    loggingBuilder.AddSerilog();
});
```

`additionalOperation` 是往 Exceptionless 事件上追加信息的钩子，通常用来把 `TraceId` 写成 tag，方便在 Exceptionless 里按链路聚合。

> 完整可运行示例见 [`samples/Bing.Samples.Hangfire`](../../samples/Bing.Samples.Hangfire/README.md)。注意样例里 `ServerUrl` 与 `ApiKey` 是硬编码的内网调试值，运行前请替换。

## 9. Analyzers — 两个编译期组件 🧩

两个包**没有运行时 API**，只在编译期生效，因此不在注册入口速查表里。

### 8.1 Bing.Data.Sql.Analyzers — 插值 SQL 安全检查

| 项 | 值 |
| --- | --- |
| 路径 | `framework/src/Bing.Data.Sql.Analyzers/` |
| TFM | `netstandard2.0` |
| 规则 ID | **`BINGSQL002`** |
| 严重级别 | `Warning`（默认启用） |
| 分类 | `Bing.Data.Sql.Security` |

规则内容：**插值字符串传入普通 SQL `string` 入口会拼接值**，提示改用 `SqlInterpolated(...)` 或显式参数对象。

```
警告 BINGSQL002：插值 SQL 未参数化
插值字符串传入普通 SQL string 入口会拼接值，请改用 SqlInterpolated(...) 或参数对象。
```

这是防 SQL 注入的编译期护栏。出现该警告时不要直接 `NoWarn` 掉，优先改为参数化写法。

### 8.2 Bing.Ddd.Domain.Extensions.Analyzers — 变更追踪源代码生成器

| 项 | 值 |
| --- | --- |
| 路径 | `framework/src/Bing.Ddd.Domain.Extensions.Analyzers/` |
| TFM | `netstandard2.0` |
| 类型 | `[Generator] ISourceGenerator`（`ChangeTrackableSourceGenerator`） |

行为：扫描继承 **`Bing.Domain.Entities.DomainObjectBase<T>`** 的候选类，为其公开实例属性生成**变更追踪**相关的 partial 代码（`AddChanges` 之类的方法）。

- 由 `DomainObjectBaseSyntaxReceiver` 收集候选类声明；
- 生成的代码是 `<auto-generated>`，会写进编译过程，不要在源码里找它；
- 你的领域类需要声明为 `partial`，且基类确实是 `DomainObjectBase<T>`，才会触发生成。

## 11. 注意事项

- **`components/src` 不在 docfx 元数据范围**：`docs/docfx.json` 的 `metadata.src` 只写了 `../framework/src`，所以 `Bing.Biz`、`Bing.Biz.Payments`、`Bing.Biz.OAuthLogin` 三个包的逐方法文档不会出现在 API 站点上。这不是配置遗漏，需要时请自行追加 `src` 条目。
