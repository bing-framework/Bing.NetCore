## 1. 扩展点地图

## 2. 新增模块

### 2.1 两个基类，别拿错

| | `BingModule` | `AspNetCoreBingModule` |
| --- | --- | --- |
| 定位 | **非 Web 宿主**（控制台、后台任务、Worker） | **Web 宿主**（ASP.NET Core） |
| 继承 | `abstract class BingModule : IBingModule`（`BingModule.cs:9`） | `class AspNetCoreBingModule : BingModule`（`AspNetCoreBingModule.cs:9`） |
| 重写点 | `AddServices(IServiceCollection)`、`UseModule(IServiceProvider)` | 同上 **＋** `UseModule(IApplicationBuilder)` |
| 启动时序 | `AddServices` → `UseModule(IServiceProvider)` | `AddServices` → `UseModule(IApplicationBuilder)`（内部转调基类的 `IServiceProvider` 版本，`AspNetCoreBingModule.cs:15`） |

⚠ **两个容易被忽略的签名细节**：

- `AddServices` 的返回类型是 **`IServiceCollection`**（不是 `void`）——`BingModule.cs:22`。写 `public override void AddServices(...)` 会编译不过。
- Web 支是**两级 `UseModule` 重载**：重写 `IApplicationBuilder` 版本时，若还需要非 Web 的初始化逻辑，记得自己调 `base.UseModule(serviceProvider)`。

### 2.2 `[DependsOnModule]` 与 `ModuleLevel`

```csharp
// DependsOnModuleAttribute.cs:6,18,24
[AttributeUsage(AttributeTargets.Class, AllowMultiple = true)]
public class DependsOnModuleAttribute : Attribute
{
    public DependsOnModuleAttribute(params Type[] dependedModuleTypes);
    public Type[] GetDependedTypes();
}
```

| 项 | 事实 |
| --- | --- |
| 语义 | **递归包含**被依赖的模块（把它们一起装进来），`AllowMultiple = true` 可标多个 |
| `ModuleLevel` 全部取值 | `Core = 1` · `Framework = 10` · `Application = 20` · `Business = 30`（`ModuleLevel.cs:11,16,21,26`） |
| `Order` 作用 | **同一 `Level` 内**的次级排序，默认 `0` |

### 2.3 真正的排序规则（最容易误解的一条）

```
OrderBy(Level) → ThenBy(Order) → ThenBy(FullName)
```

证据：`BingServiceProviderExtensions.cs:52-54`、`BingBuilder.cs:113`。

**它不是按 `[DependsOnModule]` 做拓扑排序。** 依赖只负责"把模块拉进来"，顺序完全由上面三项决定。这意味着：两个同 `Level` 且都没设 `Order` 的模块，谁先启动取决于**类型全名**——加个命名空间前缀就可能改变启动顺序。需要确定性时请显式设 `Order`。

### 2.4 最小模块模板（真实源码）

取自 `samples/Bing.Samples.WebApi/Modules/AppModule.cs`，原样：

```csharp
using System.ComponentModel;
using Bing.AspNetCore;
using Bing.Core.Modularity;

namespace Bing.Samples.WebApi.Modules;

/// <summary>应用程序模块</summary>
[Description("应用程序模块")]
[DependsOnModule(typeof(AspNetCoreModule))]
public class AppModule : AspNetCoreBingModule
{
    public override ModuleLevel Level => ModuleLevel.Application;

    public override IServiceCollection AddServices(IServiceCollection services)
    {
        services.AddControllers();
        return services;
    }

    public override void UseModule(IApplicationBuilder app)
    {
        app.UseRouting();
    }
}
```

注册：`services.AddBing().AddModule<AppModule>()`；Web 宿主最后 `app.UseBing()`。

> `AddBing()` / `AddModule<T>()` 是 `IBingBuilder` 上的扩展（**不是** `IServiceCollection`），所以链式调用的第一环必须是 `AddBing()`。完整入口见 [架构文档 §12](../architecture/架构文档.md)。

### 2.5 新增模块检查清单

- [ ] 基类选对（Web / 非 Web）
- [ ] `AddServices` 返回 `IServiceCollection`
- [ ] `Level` 设对（业务代码用 `Application` / `Business`，别用 `Core`）
- [ ] 同 `Level` 内有顺序要求 → 显式设 `Order`
- [ ] 需要别人先启动 → 标 `[DependsOnModule]`（但**别指望它管顺序**）
- [ ] 非 Web 宿主记得 `serviceProvider.UseBing()`，漏了模块只装配不初始化

## 3. 新增数据访问 Provider

三支的模板**结构差异极大**，请对照自己的支看对应小节。以 MySQL 为参照（它三支都齐）。

### 3.1 三支文件清单对照

| | EF Core 支 | FreeSQL 支 | Dapper 支 |
| --- | --- | --- | --- |
| 参照工程 | `framework/src/Bing.EntityFrameworkCore.MySql` | `framework/src/Bing.FreeSQL.MySql` | `framework/src/Bing.Dapper.MySql` |
| 源文件数 | **5 个 `.cs`** | **5 个 `.cs`** | **16 个 `.cs`** |
| 注册入口 | `AddMySqlUnitOfWork` | `AddMySqlUnitOfWork` | `AddMySqlProvider` |
| 核心契约 | `UnitOfWorkBase` | `UnitOfWorkBase` | `ISqlProvider` |

### 3.2 EF Core 支

```
Bing.EntityFrameworkCore.MySql/
├── Extensions.Service.cs      ← 注册扩展（3 个重载）
├── MySqlUnitOfWorkBase.cs     ← 工作单元基类
├── IMap.cs                    ← 映射契约
├── EntityMap.cs               ← 普通实体映射
└── AggregateRootMap.cs        ← 聚合根映射
```

注册入口签名（`Extensions.Service.cs:29-37,52-59,76-84`，3 个重载，此处取主重载）：

```csharp
public static IServiceCollection AddMySqlUnitOfWork<TService, TImplementation>(
    this IServiceCollection services,
    DbConnection connection,                 // 或 string connection
    Action<DataConfig> optionsAction = null,
    Action<DbContextOptionsBuilder> builderAction = null,
    Action<MySqlDbContextOptionsBuilder> mySqlOptionsAction = null)
    where TService : class, IUnitOfWork
    where TImplementation : UnitOfWorkBase, TService;
```

⚠ **两个泛型参数**，且第二个必须是 `UnitOfWorkBase` 的派生。只写一个泛型参数编译不过——这是从 ABP 迁过来的人最常踩的一处（见 [ABP 迁移对照](../getting-started/abp-migration.md)）。

```csharp
protected override IEnumerable<IMap> GetMapInstances(Assembly assembly)   // MySqlUnitOfWorkBase.cs:26
```

基类该方法是 `virtual`（`UnitOfWorkBase.cs:271`）；`UnitOfWorkBase` 自身实现 `IUnitOfWork, IDatabase`（`UnitOfWorkBase.cs:33`）。

### 3.4 Dapper 支（工作量最大，但也最自由）

注册入口（`DapperServiceCollectionExtensions.cs:25`）：

```csharp
public static IServiceCollection AddMySqlProvider(this IServiceCollection services);
```

⚠ **MySQL 支没有批量更新渲染器**。`ISqlBatchUpdateRenderer` 只有 PostgreSQL 支实现了（`PostgreSqlBatchUpdateRenderer.cs:14`，注册于 `DapperServiceCollectionExtensions.cs:32`），接口本身在 `Bing.Data.Sql/Bing/Data/Sql/Builders/Mutations/Batching/ISqlBatchUpdateRenderer.cs`。所以新增 Provider 时：

- **想省事** → 不实现它，批量写入会走 `Auto` 策略自动降级（逐条命令，功能正常）
- **想要 Provider 侧优化** → 参照 PostgreSQL 支补一个，并在 `DapperServiceCollectionExtensions` 里注册

PostgreSQL 支比 MySQL 支多两个文件，可作"进阶功能"参考：`PostgreSqlBatchUpdateRenderer.cs`、`PostgreSqlParamLiteralsResolver.cs`。

### 3.5 Provider 能力档案（Profile）

Profile **只被 Dapper 支使用**，用来声明"这个数据库支持哪些语法/执行能力"，从而决定能力探测走通过还是降级。

| 类型 | 位置 | 字段 |
| --- | --- | --- |
| `SqlProviderProfile` | `SqlProviderProfile.cs:207` | `Query` / `Mutation` / `Execution` / `Transaction` / `Procedure` / `Limits` |
| `SqlProviderQueryCapabilities` | `:8` | `Union` / `UnionAll` / `RightJoin` / `FullJoin` / `Pagination` 等（`SqlQueryCapabilityState`） |
| `SqlProviderMutationCapabilities` | `:54` | `SupportsMultiRowValues`(:59) / `SupportsUpdateFrom`(:69) / `SupportsDeleteUsing`(:79) / `SupportsReturning`(:89) |
| `SqlProviderExecutionCapabilities` | `:100` | `SupportsMultipleResultSets`(:105) / `SupportsStreaming`(:115) / `SupportsCancellation`(:125) |
| `SqlProviderTransactionCapabilities` | `:136` | `SupportsTransactions`(:141) / `SupportsNativeAsyncBegin`(:151) / `…Commit`(:156) / `…Rollback`(:161) |
| `SqlProviderProcedureCapabilities` | `:167` | `SupportsStoredProcedures`(:172) / `SupportsOutputParameters`(:182) |
| `SqlProviderLimits` | `:193` | `MaxParameterCount`（`int?`，null = 不限制） |

暴露方式二选一：

- 让 Provider 类**同时实现** `ISqlProviderProfileProvider`（`Profile` 属性，`:244`）——MySQL 就是这么做的：`MySqlSqlProvider : ISqlProvider, ISqlProviderProfileProvider`（`MySqlSqlProvider.cs:11`），档案内联在 `:42-81`
- 或不实现——框架有 `HasProfile` / `HasCompleteProfile` 探测（`:262`、`:272`），缺档案时按"未声明"处理（这类状态会出现在能力矩阵里，见 [功能完成度 §4.1](../architecture/功能完成度.md)）

## 4. 约定式 DI 的扩展

### 4.1 两种声明方式

```csharp
// 方式一：标记接口（最常用）
public class OrderService : IScopedDependency { }        // ISingletonDependency / ITransientDependency

// 方式二：特性（优先级更高）
[Dependency(ServiceLifetime.Singleton)]
public class CacheService : ICacheService { }
```

`DependencyAttribute` 的**全部成员**（`DependencyAttribute.cs:15,21,26,31,36`）：

| 成员 | 类型 | 默认 | 作用 |
| --- | --- | --- | --- |
| `Lifetime` | `ServiceLifetime` | **构造必填** | 生命周期。`[Dependency]` 不写生命周期参数编译不过 |
| `TryAdd` | `bool` | `false` | 用 `TryAdd` 语义，已存在则不覆盖 |
| `ReplaceExisting` | `bool` | `false` | 覆盖已有注册（**替换框架内置实现时用这个**） |
| `AddSelf` | `bool` | `false` | 额外把自身类型也注册一份 |

`[IgnoreDependency(bool cascade = false)]`（`IgnoreDependencyAttribute.cs:14,20`）：标在类或接口上排除注册；`cascade = true` 时连带其派生/实现一起排除。

> **属性优先于接口**：同时存在时以特性为准。

### 4.2 到底扫了哪些程序集

真实链路是 `DependencyModule.AddServices` → `IDependencyTypeFinder.FindAll(true)`（`DependencyModule.cs:41-45`），而 `DependencyTypeFinder.FindAllItems`（`DependencyTypeFinder.cs:29-37`）的入选条件是：

```
非抽象、非接口的类
  且 未被 [IgnoreDependency] 排除
  且 （实现 ISingletonDependency / IScopedDependency / ITransientDependency 之一
        或 带 [Dependency] 特性）
```

扫描范围是 `AppDomainAllAssemblyFinder` —— **当前 AppDomain 内的全部程序集**，不只是你自己的程序集。

**排除手段**：给类或接口打 `[IgnoreDependency]`（`DependencyTypeFinder.cs:35`、`DependencyModule.cs:152`）。第三方库里恰好实现了同名标记接口的类也会被扫进来，遇到意外的注册项时优先怀疑这一点。

### 4.3 ⚠ `IConventionalRegistrar` 是个"预留接口"

`framework/src/Bing.Core` 里有成套的 `IConventionalRegistrar`（`IConventionalRegistrar.cs:15,22,29`：`AddAssembly` / `AddTypes` / `AddType`）与 `ConventionalRegistrarBase`（`ConventionalRegistrarBase.cs:13,19,26,33,44,54,70`），抽象层次看起来很完整。

**但全仓 grep 只命中这两个类型自身——没有任何实现类，也没有任何注册调用。** 真正生效的自动注册走的是 §4.2 那条 `DependencyModule` 路径。

所以：**不要照着 `ConventionalRegistrarBase` 去扩展**，那是一条没接通的路。需要自定义注册逻辑，请写一个普通模块，在 `AddServices` 里手工 `services.Add...`。

## 5. 自定义分析器与源生成器

两个工程的**性质完全不同**，别搞混：

| 工程 | 性质 | 内容 |
| --- | --- | --- |
| `Bing.Data.Sql.Analyzers` | **诊断分析器**（`DiagnosticAnalyzer`） | 1 条规则：`BINGSQL002` |
| `Bing.Ddd.Domain.Extensions.Analyzers` | **源生成器**（`ISourceGenerator`） | `ChangeTrackableSourceGenerator`，**没有诊断规则 ID** |

`BINGSQL002`（`BingSqlDiagnosticDescriptors.cs:13-25`）：名称"插值 SQL 未参数化"，级别 **`Warning`**，分类 `Bing.Data.Sql.Security`，实现类 `UnsafeInterpolatedSqlAnalyzer`（`UnsafeInterpolatedSqlAnalyzer.cs:13,17`）。

> 变更追踪源生成器的用法与"静默不生成"的陷阱见 [领域建模指南 §7](领域建模指南.md)。

**新增一条诊断规则要动两处**：

1. `BingSqlDiagnosticDescriptors.cs` —— 加一个 `DiagnosticDescriptor` 常量
2. `DiagnosticAnalyzer` 的 `SupportedDiagnostics` —— 挂上去（`UnsafeInterpolatedSqlAnalyzer.cs:16-17`）

打包由 csproj 决定：分析器需输出到 `analyzers/dotnet/cs`（`Bing.Data.Sql.Analyzers.csproj:18`）。

## 6. 其它扩展点

### 6.1 替换异常 → 错误信息转换器

```csharp
public interface IExceptionToErrorInfoConverter          // IExceptionToErrorInfoConverter.cs:16
{
    RemoteServiceErrorInfo Convert(Exception exception,
        Action<BingExceptionHandlingOptions> optionsAction = null);
}
```

默认实现 `DefaultExceptionToErrorInfoConverter : IExceptionToErrorInfoConverter, ITransientDependency`（`DefaultExceptionToErrorInfoConverter.cs:13`）——**靠约定式 DI 自动进容器**。

替换方式：实现同一接口，标 `[Dependency(ServiceLifetime.Transient, ReplaceExisting = true)]`。

消费点是异常过滤器与中间件：`BingExceptionFilter.cs:90`、`BingExceptionHandlingMiddleware.cs:86`。异常体系的整体设计见 [ADR-0008](../architecture/adr/ADR-0008-exception-hierarchy.md)。

### 6.2 自定义全局过滤器 ⚠

```csharp
public abstract class FilterBase<TFilterType> : IFilter<TFilterType>   // FilterBase.cs:14
{
    public abstract Expression<Func<TEntity, bool>> GetExpression<TEntity>();
    // + IsEnabled / IsEntityEnabled<TEntity>() / Enable() / Disable()
}

public interface IFilterManager : IFilterSwitch, IScopedDependency   // IFilterManager.cs:15
{
    IFilter<TFilterType> GetFilter<TFilterType>();
    IFilter GetFilter(Type filterType);
    bool IsEntityEnabled<TEntity>();
    bool IsEnabled<TFilterType>();
}
```

**这里是本文最重要的一条警告**：`FilterManager.IsEntityEnabled<TEntity>()` **硬编码只查 `ISoftDelete` 过滤器**（`FilterManager.cs:90-94`）。所以你写一个 `FilterBase<T>` 自定义过滤器并注册进 `IFilterManager`，**它不会自动变成 EF 的 `HasQueryFilter`**。

正确做法是**重写工作单元的过滤器表达式**：

```csharp
protected override Expression<Func<TEntity, bool>> CreateFilterExpression<TEntity>()
```

完整代码见 [recipes/multi-tenancy.md](recipes/multi-tenancy.md)；结论口径见 [能力矩阵 §3.4](../getting-started/能力矩阵.md) 与 [功能完成度](../architecture/功能完成度.md)。

> 这个错误很隐蔽：照错的方式写，代码能跑、软删除也正常，**只是多租户数据会串**。

### 6.3 自定义多租户解析

```csharp
public interface ITenantResolveContributor            // ITenantResolveContributor.cs:11,17
{
    string Name { get; }
    Task ResolveAsync(ITenantResolveContext context);
}
```

- 基类 `TenantResolveContributorBase`（`TenantResolveContributorBase.cs:6`）
- 注册进 `BingTenantResolveOptions.TenantResolvers`（`List<ITenantResolveContributor>`，`BingTenantResolveOptions.cs:16`）——**集合顺序就是解析顺序**，先命中的先用
- 现成扩展只有 `AddDomainTenantResolver`（`BingTenantResolveOptionsExtensions.cs:16`），其它解析器直接往集合里加

解析链的完整设计见 [ADR-0006](../architecture/adr/ADR-0006-multi-tenancy-resolve-chain.md)，可运行代码见 [recipes/multi-tenancy.md](recipes/multi-tenancy.md)。

## 7. 扩展前检查清单

- [ ] 我要加的是**模块**还是**扩展点**？——能靠 `AddServices` 里的几行注册解决，就别新增模块
- [ ] 新增 Provider 时，**先确认自己走哪一支**：三支的模板与注册入口完全不同（§3.1）
- [ ] `AddMySqlUnitOfWork` 有两个同名不同义版本（EF 支 / FreeSQL 支）——`using` 写错就装错支
- [ ] 自定义过滤器 → 重写 `CreateFilterExpression<T>`，**不要**只注册 `IFilterManager`（§6.2）
- [ ] `ConventionalRegistrarBase` 是空壳，别照着它扩展（§4.3）
- [ ] 新增公开 API → 更新 `PublicAPI.Unshipped.txt`，否则 RS0016 会把构建打红（见 [测试指南](../operations/测试指南.md)）
- [ ] 新增工程 → 同目录补 `README.md`（会内嵌进 nupkg，见 [工程化文档](../operations/工程化文档.md)）
- [ ] 文档同步：新注册入口要同时更新 [架构文档 §12](../architecture/架构文档.md) **与** [使用文档 §3.3](../getting-started/使用文档.md)
