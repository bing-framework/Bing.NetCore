# 配置参考

> **适用版本**：框架 `7.0.0`（`version.props`）｜ 目标框架：类库 `netstandard2.0`、Web / 应用 `net6.0`｜ 内容核对：2026-09-18｜ 版本历史见 [发行说明](../ReleaseNotes.md)

> **一句话定位**：本文回答**"某个行为想调，改哪个配置项？配置节叫什么？默认值是多少？"**
>
> 先给你一个可能意外的结论：**本框架绝大多数配置走代码，而不是走 `appsettings.json` 绑定**（见 §1）。全仓真正绑定到配置节的 Options **只有一个**——`JwtOptions`（见 §4）。
>
> 安装与启动见 [使用文档](../getting-started/使用文档.md)；全部注册入口见 [架构文档 §12](../architecture/架构文档.md)；日志与追踪的接入见 [日志与可观测性](../operations/日志与可观测性.md)。
>
> **所有默认值均取自源码**。默认值判断依据是属性初始化器；标"无默认"意味着不赋值就是 CLR 默认值（`null` / `0` / `false`）。

## 1. 先理解：三类配置来源

在读下面的大表前，先分清某个 Options 属于哪一类——**这决定了你能不能在 `appsettings.json` 里配它**。

| 类别 | 特征 | 怎么配 | 典型代表 |
| --- | --- | --- | --- |
| **① 配置节绑定** | 有明确的配置节名，`IConfiguration` 绑定到 Options | `appsettings.json` | **`JwtOptions`（唯一一个）** |
| **② 代码配置** | 无配置节，靠 `AddXxx(...)` 的委托参数或 `Configure<T>(...)` | 启动代码 | `BingLoggingOptions`、`EmailOptions`、`RequestResponseLoggerOptions`、`CorrelationIdOptions` |
| **③ 不绑定** | 只是承载参数的普通类，不参与 `IOptions` 体系 | 作为方法参数传入 | `SqlOptions`、`DataConfig`、`CacheOptions` |

⚠ **把 ②③ 类的配置写进 `appsettings.json` 是无效的**——框架没有任何代码去读它。这是配置类问题里最常见的一个误判。

### 配置节名从哪来

全仓的绑定模式共三种，按使用量排序：

| 模式 | 写法 | 实例 |
| --- | --- | --- |
| 代码 Bind | `services.Configure<T>(o => configuration.GetSection(nameof(T)).Bind(o))` | `JwtOptions`（`Extensions.Service.cs:45`） |
| 委托 Configure | `services.Configure<T>(o => { ... })` | `CorrelationIdOptions`、`RealIpOptions`、`ApiBehaviorOptions`（`AppModule.cs:62,77`；`Extensions.ApplicationBuilder.cs:44`） |
| 特性驱动 | `[OptionsType("节名")]` → `AddOptionsType` 动态注册 `IConfigureOptions<T>` | 机制在 `Bing.Core/Bing/Configuration/Extensions.ServiceCollection.cs:19-76`，⚠ **全仓无一处实际使用** |

`[ConfigurationKeyName]`：**全仓未使用**。

## 2. `AddBing()` 到底能配什么 ⚠

```csharp
public static IServiceCollection AddBing(
    this IServiceCollection services,
    Action<BingOptions> setupAction = null)      // ServiceCollectionApplicationExtensions.cs:21
```

**`BingOptions` 是空类**（`Bing.Core/Bing/Options/BingOptions.cs:6`），基类 `BingOptionsBase` 也只有 `Extensions` 列表与 `AddExtension(...)`（`BingOptionsBase.cs:6-31`）。

所以：

- ❌ **没有 `EnableAop`** —— AOP 入口是 **`services.EnableAop(...)`**，`IServiceCollection` 上的独立扩展，参数是 `Action<IAspectConfiguration>`（`AspectCoreExtensions.cs:26`）
- ❌ 没有 `EnableAuditing` / `EnableValidation` / `EnableCaching` 之类开关
- ✅ 唯一可用成员是继承来的 `AddExtension(IBingOptionsExtension)`——用于注册扩展，`Extensions` 列表会被逐个执行 `extension.AddServices`（同文件 `:40-41`）

```csharp
// 正确写法：AddBing 只负责启动模块系统，配置项各自独立
services.AddBing();                  // 或 AddBing(o => o.AddExtension(new MyExtension()))
services.EnableAop(o => { ... });    // AOP 在别处
```

> 这个空类是**故意的设计**——保持 `AddBing()` 的入口稳定，各能力通过独立扩展挂载。但对使用者不友好：凭直觉写 `o.EnableAop = true` 会编译不过，且报错信息只说"没有这个属性"，不告诉你该去哪找。

## 3. 配置加载顺序

框架**没有**自定义 `IConfigurationBuilder` 扩展，也没有重排默认源（全仓 `AddJsonFile` / `IConfigurationBuilder` 无命中）。

加载顺序完全沿用宿主：

```
Host.CreateDefaultBuilder(args)
  → appsettings.json
  → appsettings.{Environment}.json
  → 环境变量
  → 命令行参数
```

框架只提供只读辅助：`GetConfiguration()` / `GetConfigurationOrNull()`（`ServiceCollectionConfigurationExtensions.cs:28,36`）与 `Print()` 打印扩展（`Extensions.ServiceCollection.cs:83`）。

## 4. 唯一绑定配置节的 Options：`JwtOptions`

```jsonc
// modules/admin/src/Bing.Admin/appsettings.json（值已遮蔽）
"JwtOptions": {
  "Issuer": "bing_identity",
  "Audience": "bing_client",
  "Secret": "***",
  "AccessExpireMinutes": 0,
  "RefreshExpireMinutes": 0,
  "ThrowEnabled": false
}
```

| 属性 | 默认值 | 说明 |
| --- | --- | --- |
| `Secret` | **无默认** | 对称密钥。`ThrowEnabled=true` 时密钥缺失的后果见 [安全指南](../operations/安全指南.md) |
| `Issuer` | `"bing_identity"` | 签发者 |
| `Audience` | `"bing_client"` | 受众 |
| `AccessExpireMinutes` | `0` | 访问令牌有效期（分钟）。**0 的含义请务必确认**——与 `ThrowEnabled` 组合会改变过期校验行为 |
| `RefreshExpireMinutes` | `0` | 刷新令牌有效期 |
| `ThrowEnabled` | `false` | ⚠ **置 `true` 会走到不校验 `exp`/`nbf` 的分支**，详见 [安全指南](../operations/安全指南.md) |
| `SingleDeviceEnabled` | `false` | 单设备登录（踢前一次登录） |

绑定代码：`Extensions.Service.cs:45`（`Bind`）与 `:75`（`Get<JwtOptions>()`）。

> ⚠ 同一份 `appsettings.json` 里的 `Secret` 与连接串**是真实值且已提交进版本库**。处置方式见 [安全指南](../operations/安全指南.md)，此处不复现任何明文。

## 7. 连接字符串约定

| 键名 | 使用方 |
| --- | --- |
| `DefaultConnection` | `modules/admin` 的 EF 工作单元（`EntityFrameworkCoreModule.cs:38`）、CAP（`CapModule.cs:43`） |
| `RedisConnection` | 缓存（`CacheModule.cs:37`） |
| `Default` | **框架默认键名**（`Bing.Data/ConnectionStringCollection.cs:12`） |

测试工程另用：`MySqlConnection`、`PostgreSqlConnection`、`SqlServerConnection`、`reporting`、`Slave`。

`GetConnectionString` 未命中时会**回退到默认键**（`ConnectionStringCollection.cs:28`）——写了错键名不会报"找不到"，而是静默连到默认库。改连接串没生效时优先查这一点。

## 8. 环境变量

- **框架层没有** `AddEnvironmentVariables` / `AddUserSecrets` / 前缀约定（`framework/src` 无命中）
- 宿主用 `Host.CreateDefaultBuilder`（`Program.cs:23`），因此标准的 `ASPNETCORE_` / `DOTNET_` 前缀环境变量由 .NET 默认加载
- 测试场景会显式加环境变量（如 `framework/tests/Bing.Dapper.SqlServer.Tests.Integration/Startup.cs:44`）
- 测试门控变量（`RUN_INTEGRATION_TESTS` 等）见 [测试指南](../operations/测试指南.md)
- `Bing.Logging.Serilog` 的 `EnvironmentEnricher` 按变量名读取环境变量（`EnvironmentEnricher.cs:26`），**无固定前缀**

> 想把 admin 的凭据移出 `appsettings.json`，环境变量是可行路径之一（`Host.CreateDefaultBuilder` 已支持），但**要注意它已被 git 跟踪**——只改文件不改历史无法真正消除泄露，见 [安全指南](../operations/安全指南.md)。

## 9. 常见误区

| # | 误区 | 事实 |
| --- | --- | --- |
| 1 | `AddBing(o => o.EnableAop = true)` | **`BingOptions` 是空类**。AOP 用 `services.EnableAop(...)` |
| 2 | 把日志/缓存/邮件配置写进 `appsettings.json` | 这些是**代码配置**类（②③），框架不读配置节 |
| 3 | 以为 `[OptionsType]` 能绑配置节 | 机制存在，但**全仓零使用**；唯一实际绑定的是 `JwtOptions` |
| 4 | 连接串键名写错 | `GetConnectionString` **静默回退到 `Default`**，表现为"改了配置没生效" |
| 5 | `JwtOptions.ThrowEnabled = true` 只是"抛异常" | 它会切到**不校验令牌有效期**的分支，见 [安全指南](../operations/安全指南.md) |
| 6 | 以为框架有 CAP / Swagger / Hangfire 的配置节 | 一律走 `AddCapEventBus(...)` / `AddSwagger(...)` / `AddHangfire(...)` |
